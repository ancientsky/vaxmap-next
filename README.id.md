# Peta Vaksin dan Antivirus Influenza (vaxmap-next)

**語言／Language：** [繁體中文](README.md) ・ [English](README.en.md) ・ [日本語](README.ja.md) ・ [한국어](README.ko.md) ・ Bahasa Indonesia ・ [Tiếng Việt](README.vi.md) ・ [ไทย](README.th.md) ・ [Filipino](README.tl.md)

Ini adalah **concept prototype (Proof of Concept)** dari "Peta Vaksin dan Antivirus Influenza" (vaxmap.cdc.gov.tw) milik Pusat Pengendalian Penyakit Taiwan, Kementerian Kesehatan dan Kesejahteraan (Taiwan CDC),
yang dibuat untuk mendemonstrasikan pengalaman front-end yang lebih cepat dan lebih mudah digunakan daripada situs yang berjalan saat ini. **Ini bukan situs resmi**, tidak di-deploy pada domain pemerintah mana pun, dan datanya
**bukan data real-time**, melainkan snapshot yang diambil dari situs saat ini dua kali sehari (snapshot pertama 2026-09-21; mekanisme pembaruan dijelaskan di bagian "Cara data diperbarui" dan "Deploy ke GitHub Pages"). Jika Anda mengambil alih proyek ini,
sebaiknya baca lebih dulu `docs/DATA_SCHEMA.md` (kontrak data front-end) dan `docs/HARVEST.md` (asal snapshot dan keterbatasannya).

## Apa dan bukan apa proyek ini

- Ya: prototipe situs statis murni yang berjalan hanya dengan membaca satu berkas JSON, untuk memperlihatkan desain baru untuk filter, daftar, interaksi peta, dan URL yang dapat dibagikan.
- Bukan: sistem produksi, sumber data real-time, atau pengganti situs saat ini. Jarak, stok, dan jam praktik semuanya merupakan data pada saat snapshot,
  **sehingga sebelum vaksinasi, selalu hubungi fasilitas kesehatan lebih dulu melalui telepon**.

## Menjalankan secara lokal

Server pengembangan secara bawaan hanya di-bind ke mesin lokal (127.0.0.1); agar ponsel di jaringan yang sama dapat terhubung untuk pengujian, jalankan dengan `HOST=0.0.0.0 npm run dev`.

Kebutuhan: Node.js 18 atau lebih baru (`"type": "module"`, memakai ES modules dan `node:test`). Proyek ini **tidak memiliki proses build**:
isi `public/` sudah merupakan artefak yang siap di-deploy, dan `leaflet`／`leaflet.markercluster` hanya tercantum di `devDependencies`,
untuk keperluan membuat ulang berkas bundel di bawah `public/vendor/` di kemudian hari; `npm install` tidak diperlukan untuk menjalankan situs di produksi.
Satu-satunya pengecualian adalah **pembuatan data**: `scripts/normalize.mjs` memakai `pinyin-pro` (devDependency, kamus lokal, tanpa koneksi jaringan) untuk menghasilkan transliterasi bahasa Inggris,
sehingga `npm install` perlu dijalankan sebelum `npm run normalize`／`update-data` (`publish-data.sh` akan menjalankan `npm ci` secara otomatis bila paket belum ada).

```bash
npm run dev        # Start http://localhost:5173/ (override with the PORT environment variable)
```

## Menjalankan pengujian

```bash
npm test           # Unit tests + data quality tests (node --test)
npm run test:e2e   # Playwright end-to-end smoke tests (desktop 1440x900, mobile 390x844)
npm run test:a11y  # Accessibility checks (reports issues only, never modifies any file)
```

`test:e2e` dan `test:a11y` mengharuskan `playwright` sudah terpasang secara global di lingkungan (proyek ini mengasumsikan versi 1.56) dan browser sudah terpasang sebelumnya
(`PLAYWRIGHT_BROWSERS_PATH` menunjuk ke direktori tempat Chromium terpasang); kedua skrip ini akan menjalankan sendiri
`scripts/dev-server.mjs` pada port acak yang tersedia dan menutupnya otomatis setelah pengujian selesai, sehingga **tidak perlu menjalankan server secara manual**.

## Deploy

`public/` adalah satu-satunya direktori yang perlu dipublikasikan; salin ke host statis apa pun (Nginx, IIS, S3+CDN, GitHub Pages, dan sebagainya),
tanpa memerlukan program sisi server maupun basis data.

### Catatan deploy di IIS

- **Tipe MIME**: pastikan `.json` dipetakan ke `application/json` (di IIS biasanya sudah bawaan; jika belum, tambahkan di
  `web.config` berikut: `<staticContent><mimeMap fileExtension=".json" mimeType="application/json" /></staticContent>`).
- **Kompresi statis**: aktifkan Static Compression di IIS (`httpCompression`／`urlCompression`).
  `hospitals.json` berukuran sekitar 1,9 MB tanpa kompresi dan turun menjadi sekitar 330 KB dengan gzip, yang sangat berpengaruh bagi pengguna jaringan seluler.
- **Header HTTP yang disarankan**:
  | Header | Nilai yang disarankan | Alasan |
  |---|---|---|
  | `Content-Security-Policy` | Sinkronkan ke tingkat server sesuai pengaturan `<meta http-equiv>` yang sudah ada di `public/index.html` (`frame-ancestors 'none'` harus diatur pada header HTTP; tag `<meta>` tidak dapat mendeklarasikan `frame-ancestors`) | Mencegah penyematan dalam iframe (clickjacking) dan membatasi sumber skrip／gaya |
  | `X-Content-Type-Options` | `nosniff` | Menghindari risiko akibat browser menebak tipe MIME |
  | `Referrer-Policy` | `strict-origin-when-cross-origin` | Sudah diatur melalui `<meta name="referrer">`; dapat ditambahkan lagi di tingkat server sebagai lapisan tambahan |
  | `X-Frame-Options` | `DENY` (jika CSP `frame-ancestors` tidak digunakan) | Alasan sama seperti di atas; langkah pengaman untuk browser yang lebih lama |
- **Strategi cache**:
  | Path | Cache yang disarankan | Alasan |
  |---|---|---|
  | `data/hospitals.json` | Cache singkat (misalnya `Cache-Control: no-cache` atau `max-age=60~300`) | Data diperbarui secara berkala; cache yang terlalu lama membuat pengguna melihat stok yang sudah kedaluwarsa |
  | `vendor/**`、`css/**`、`js/**` | Cache panjang + pemberian versi (misalnya `max-age=31536000, immutable`, disertai nomor versi pada nama berkas atau query string) | Hanya perlu diinvalidasi saat isi berubah, sehingga unduhan berulang berkurang banyak |
  | `index.html` | Cache singkat atau tanpa cache | Memastikan pengguna mendapat referensi sumber daya terbaru |

  Saat ini `scripts/dev-server.mjs` (hanya untuk pengembangan lokal) mengirim `Cache-Control: no-cache` untuk semua berkas; di lingkungan produksi,
  atur sesuai tabel di atas pada lapisan IIS／CDN. Isi `public/` sendiri tidak perlu diubah.

## Cara data diperbarui (cara saat ini)

`npm run update-data` menjalankan tiga hal secara berurutan: `scripts/harvest.mjs` mengambil data fasilitas kesehatan se-Taiwan dari situs saat ini dan menyimpannya sebagai
`data/raw/vaxmap_raw_YYYYMMDD-HHmm.json.gz`; `scripts/normalize.mjs` mengonversi berkas mentah terbaru menjadi
`public/data/hospitals.json` (kontrak format ada di `docs/DATA_SCHEMA.md`); terakhir, pemeriksaan data dijalankan. Jika salah satu langkah gagal, proses dihentikan,
sehingga tidak ada data setengah jadi yang terpublikasi. Detail dan batasan pengambilan data ada di `docs/HARVEST.md`.

Satu kali pengambilan penuh mengirim sekitar 280 permintaan ke situs saat ini, mentransfer hampir 100 MB, dan memakan waktu 10–15 menit. Data sumber itu sendiri dilaporkan setiap hari oleh fasilitas kesehatan,
sehingga **memperbarui 1–2 kali sehari sudah cukup; jangan menaikkan frekuensi atau memperkecil jeda antarpermintaan**. Situs saat ini tidak menerima koneksi dari luar negeri, sehingga pengambilan data harus dijalankan pada mesin di dalam negeri (Taiwan); cara pembaruan otomatis bersama GitHub Pages dijelaskan di bagian berikutnya.

Ini masih merupakan **cara sementara**; cara resmi adalah mengekspor data langsung dari sisi server (lihat "Cara integrasi data resmi yang disarankan").

**Bagian info vaksinasi** (`public/data/info/<lang>.json`) memiliki pipeline tersendiri: `npm run update-info` menjalankan secara berurutan
`scripts/harvest-info.mjs` (mengambil halaman "Zona Vaksinasi" Taiwan CDC, mengurai setiap kartu menjadi paragraf, daftar, tabel, tautan, dan lampiran,
membersihkannya dengan daftar putih, lalu menulis ke `data/info/source.json`), `scripts/translate-info.mjs` (hanya mengirim blok yang isinya berubah ke Google Gemini API
[`gemini-3.5-flash-lite`] untuk diterjemahkan ke 7 bahasa; hasilnya di-cache di `data/info/translations.json`, blok yang tidak berubah tidak dikirim ulang; bila `GEMINI_API_KEY` tidak diatur, tidak ada yang diterjemahkan,
dan berkas bahasa asing dikeluarkan dengan teks asli Mandarin Tradisional serta ditandai belum diterjemahkan), dan terakhir memvalidasi 8 berkas keluaran. Bila halaman tidak dapat diakses atau tata letaknya berubah, tidak ada berkas yang ditulis, dan situs tetap memakai versi sebelumnya.
Situs resmi Taiwan CDC (`www.cdc.gov.tw`) dapat diakses dari luar negeri, sehingga pipeline ini berjalan otomatis setiap hari di GitHub Actions (`.github/workflows/info-update.yml`,
pukul 06:00 Taipei time) tanpa memerlukan mesin di dalam negeri. Hanya satu halaman diambil sekali jalan; biaya terjemahan untuk perubahan satu blok yang tipikal sekitar US$0,01; detail, perkiraan biaya, pemicuan manual, dan cara memaksa terjemahan ulang ada di
`docs/INFO_PIPELINE.md`.

## Halaman info vaksinasi (info.html)

Selain peta, situs memiliki halaman "Info Vaksinasi" (`public/info.html`, dapat dibuka dari navigasi header), yang isinya disinkronkan dari situs resmi Taiwan CDC
"Zona Vaksinasi 115 (2026) 左流右新護肺顧心" dan ditata ulang menjadi kartu yang mudah dibaca: koin kesehatan (berapa koin untuk masing-masing dari tiga vaksin), sasaran vaksinasi yang dibiayai pemerintah
(tabel tahap pertama／kedua; di ponsel berubah menjadi kartu), tempat vaksinasi (termasuk tombol "Buka peta" dan tautan dinas kesehatan setiap kabupaten／kota), hal yang perlu diperhatikan dan materi edukasi kesehatan
(PDF／video), merek vaksin, tanya jawab umum, dan tautan siaran pers. Setiap blok menampilkan tanggal pembaruan terakhir sumbernya dan tautan kembali ke bagian tersebut di situs resmi.
Tersedia dalam delapan bahasa: Mandarin Tradisional adalah teks asli, sisanya terjemahan mesin (kumpulan pertama diimpor dari draf yang sudah dikoreksi manusia, selanjutnya setiap hari hanya blok yang berubah yang diterjemahkan otomatis);
blok yang belum diterjemahkan diberi tanda dan menampilkan teks asli. Front-end hanya membaca `public/data/info/<lang>.json`, semua teks ditulis sebagai teks biasa, dan tautan dibatasi ke
`*.gov.tw`／`*.gov.taipei`／YouTube (lihat `docs/INFO_SCHEMA.md`). Mekanisme pembaruan dijelaskan di "Cara data diperbarui"; kodenya ada di
`public/js/info*.js`, dan pengujiannya adalah `tests/e2e-info.spec.mjs` dan `tests/info-ui.test.mjs`.

## Multibahasa

Antarmuka mendukung Mandarin Tradisional (bawaan), English, 日本語, 한국어, Bahasa Indonesia, Tiếng Việt, ไทย, dan Filipino,
yang dapat diganti lewat menu ikon globe di header (tanpa memuat ulang halaman). Bahasa diambil berurutan dari URL `#lang=en`, pilihan terakhir (localStorage),
bahasa browser, dan bila tidak ada maka Mandarin Tradisional; bahasa non-bawaan ditulis ke dalam URL yang dapat dibagikan. Nama kabupaten／kota diterjemahkan, dan pencarian dapat memakai nama kabupaten／kota dalam bahasa asing (misalnya “Taipei”).

**Transliterasi bahasa Inggris untuk nama dan alamat fasilitas kesehatan**: setiap fasilitas di `hospitals.json` juga memiliki `nameEn`, `addrEn`, `cityEn`, `distEn`
(dihasilkan oleh `scripts/romanize.mjs` berbasis aturan: istilah medis diterjemahkan ke bahasa Inggris lewat glosarium, nama diri memakai Hanyu Pinyin, kabupaten／kota dan distrik memakai nama Inggris resmi,
alamat mengikuti urutan alamat bahasa Inggris versi kantor pos, misalnya「林文正耳鼻喉科診所」→ “Linwenzheng ENT Clinic”、「臺北市北投區明德路92號1樓」→
“1F, No. 92, Mingde Rd., Beitou District, Taipei City”). `meta.script` pada berkas bahasa menentukan cara tampilan: `latin` (en, ko, id, vi, th, tl)
menampilkan bahasa Inggris sebagai yang utama dan teks asli Mandarin di baris kedua (memudahkan untuk ditunjukkan kepada sopir taksi atau petugas meja); `han` (Mandarin Tradisional, Jepang)
menampilkan Mandarin sebagai yang utama, dan untuk bahasa Jepang ditambahkan nama dalam bahasa Inggris.
Pencarian di bahasa apa pun mencocokkan kolom Mandarin dan Inggris sekaligus (“Beitou”, “Mingde”, “ENT”, “Lin Wen Zheng” semuanya dapat ditemukan). Transliterasi dihasilkan oleh aturan mesin,
bukan terjemahan resmi, sehingga sebagian kecil nama atau alamat mungkin tidak sepenuhnya akurat.

- **Lokasi string**: `public/i18n/<lang>.json`, berupa pemetaan key → string yang datar; `zh-Hant.json` adalah teks asli.
- **Aturan key**: dikelompokkan dalam namespace menurut fitur (`filters.today`, `detail.call`, `status.ok.text`); parameter seperti `{n}` wajib dipertahankan;
  gunakan `<key>.one` bila jumlahnya tepat 1; tidak boleh berisi HTML. Setiap berkas bahasa harus memiliki key yang persis sama dengan bahasa Mandarin Tradisional (diperiksa oleh `npm test`).
- **Menambah bahasa**: tambahkan kode ke `SUPPORTED_LANGS` di `logic.js` → salin `en.json`, ubah `meta.*`, atur `"_status": "placeholder"`
  → tambahkan opsi ke `#lang-select` di `index.html` → `npm test`. Langkah rinci dan glosarium istilah medis ada di `docs/I18N.md`.
- **Status tinjauan** (`_status` di dalam berkas): `zh-Hant` adalah teks asli dan `en` sudah selesai; `ja`, `ko`, `id`, `vi`, `th`, `tl` berstatus
  `placeholder` (sementara ditampilkan dalam bahasa Inggris, menunggu terjemahan).

## Deploy ke GitHub Pages (termasuk pembaruan data harian otomatis)

**Prasyarat penting: situs Taiwan CDC saat ini tidak menerima koneksi dari luar negeri.** Pada pengujian 2026-09-21, mesin eksekusi GitHub Actions (berlokasi di luar negeri) mengalami timeout koneksi saat terhubung ke
`vaxmap.cdc.gov.tw` (`UND_ERR_CONNECT_TIMEOUT`). Karena itu pengambilan data fasilitas tidak dapat dijalankan di GitHub,
dan diubah menjadi "pengambilan data fasilitas di mesin dalam negeri"; sumber bagian info vaksinasi adalah situs resmi Taiwan CDC `www.cdc.gov.tw`, yang dapat diakses dari luar negeri (pengujian 2026-09-29: HTTP 200),
sehingga seluruh pipeline info vaksinasi berjalan di GitHub Actions, dan kunci terjemahan juga hanya disimpan di GitHub:

```
Linux machine in Taiwan (daily at 05:30, 12:30)  GitHub
  scripts/publish-data.sh
    ├─ harvest.mjs harvest → normalize.mjs → data checks
    ├─ push-data-branch.sh: hospitals.json ────────►  data branch (always a single commit, so the repo does not grow)
    └─ gh workflow run deploy.yml ─────────────────►  deploy.yml: take the site from main + the newer data from the data branch
                                                       → run sanitizing and checks again → deploy to Pages
                                                    info-update.yml (daily at 06:00, runs on GitHub)
                                                      ├─ fetch the previous data branch version (translation cache)
                                                      ├─ harvest-info → translate-info (Gemini) → check
                                                      ├─ push-data-branch.sh: info/*.json ──► data branch
                                                      └─ trigger deploy.yml only if the visible content changed
```

`.github/workflows/deploy.yml` berjalan saat ada push ke `main`, atau saat dipicu secara manual／oleh `publish-data.sh`／oleh `info-update.yml`: ia mengambil `hospitals.json` dari cabang `data`,
membersihkannya lewat `scripts/keep-live-data.mjs --file` dan memastikan bahwa ia lebih baru daripada snapshot di `main` sebelum dipakai; bila tidak ada cabang `data`,
snapshot di `main` tetap digunakan. `.github/workflows/freshness.yml` memeriksa data di cabang `data` setiap hari pukul 09:00 Taipei time (UTC+8);
bila lebih dari 36 jam tidak diperbarui, eksekusi tersebut dibuat gagal dan GitHub mengirim email kepada pemilik repo (artinya mesin pengambil data tidak berjalan atau terus gagal);
"Snapshot data" pada tampilan situs juga akan menampilkan "sudah N hari belum diperbarui".

Bagian info vaksinasi diperbarui oleh `.github/workflows/info-update.yml`: setiap hari pukul 06:00 Taipei time menjalankan `harvest-info.mjs` dan `translate-info.mjs`, lalu menulis
`info/<lang>.json` bersama teks asli `info/source.json` dan cache terjemahan `info/translations.json` ke cabang `data` (dengan begitu cache tetap terjaga antarproses,
dan blok yang tidak berubah tidak diterjemahkan ulang dengan biaya lagi; bila sumber tidak berubah dan semua bahasa sudah diterjemahkan, API terjemahan sama sekali tidak dipanggil); bila tampilan situs tidak berubah, deploy tidak dipicu.
Cabang `data` dengan demikian memiliki dua penulis, dan keduanya menulis hanya melalui `scripts/push-data-branch.sh`: hanya menimpa berkas yang menjadi tanggung jawabnya (mesin dalam negeri hanya menyentuh `hospitals.json`,
workflow hanya menyentuh `info/*`), dan mendorong dengan `--force-with-lease`; bila penulis lain kebetulan mendorong pada saat yang sama, data diambil ulang dan dicoba lagi, sehingga keduanya tidak saling menimpa (lihat `docs/INFO_PIPELINE.md`).
Bila salah satu pihak gagal, data pihak lain tetap diperbarui, dan yang gagal memakai versi sebelumnya. `deploy.yml` mengambil `info/<lang>.json` dari cabang `data`, memverifikasi tiap berkas dengan
`scripts/keep-live-data.mjs --info-dir` (pemeriksaan ketat oleh `sanitize-info.mjs`) dan memastikan berkas itu lebih baru daripada yang ada di `main` sebelum dipakai; bila cabang `data` tidak memiliki berkas-berkas ini,
versi di `main` tetap digunakan. `freshness.yml` juga memeriksa waktu pengambilan terakhir di `info/source.json`; bila lebih dari 36 jam, hanya peringatan yang dikeluarkan (tanpa email);
yang diperiksa adalah waktu pengambilan, bukan isi sumber, sehingga halaman Taiwan CDC yang tidak berubah selama beberapa hari tidak menimbulkan alarm palsu.

**Kunci terjemahan**: kunci Google Gemini API disimpan sebagai Actions secret `GEMINI_API_KEY` di repo (cara pengaturannya ada pada langkah 5 di bawah), dan hanya diberikan ke program pada langkah "Terjemahan" di `info-update.yml`;
kunci tidak masuk git dan tidak berada di mesin dalam negeri. Bila belum diatur, semuanya berjalan seperti biasa, hanya saja halaman bahasa asing menampilkan teks asli Mandarin Tradisional; setelah diatur, eksekusi berikutnya (atau Run workflow manual)
akan melengkapi terjemahannya. Pemicuan manual dan terjemahan ulang paksa: Actions → "接種資訊更新" → Run workflow; `force` dikosongkan = eksekusi biasa, `deploy` = deploy meskipun sumber tidak berubah,
`all`／`title`／id blok = terjemahkan ulang bagian tersebut, dan `langs` dapat membatasi bahasa (misalnya `en,ja`); lihat "Pemicuan manual／terjemahan ulang paksa" di `docs/INFO_PIPELINE.md`.
(`~/.config/vaxmap-updater/env` versi lama di mesin dalam negeri tidak dipakai lagi; bila berisi `ANTHROPIC_API_KEY`, hapus berkas itu.)

Pengaturan pertama kali:

1. Buat repo publik di GitHub dan push proyek ini ke sana (cabang bawaan harus `main`).
2. Buka Settings → Pages pada repo, atur Source ke **GitHub Actions**, lalu jalankan ulang alur "deploy" satu kali.
3. Pada satu mesin Linux yang **berada di dalam negeri dan dapat terhubung ke situs saat ini** (memerlukan git, Node.js 20 atau lebih baru, dan GitHub CLI yang sudah menjalankan `gh auth login`),
   masuk ke folder proyek dan coba secara manual terlebih dahulu: `npm run publish-data`. Jika berhasil, waktu snapshot di situs akan diperbarui dalam 10–15 menit.
4. Jalankan `scripts/install-updater.sh` untuk memasang jadwal harian. Skrip ini akan membuat sebuah folder khusus tersendiri
   (`~/.local/share/vaxmap-updater`, terpisah dari folder tempat Anda mengubah kode, dan menyinkronkan `main` secara otomatis sebelum setiap eksekusi),
   serta mengatur timer pengguna systemd; jadwal yang terlewat karena mesin mati akan dijalankan susulan setelah menyala. Untuk menghapus, gunakan `scripts/install-updater.sh --uninstall`.
5. Untuk menerjemahkan bagian info vaksinasi: buat kunci Gemini API di Google AI Studio (https://aistudio.google.com/apikey), lalu
   di repo Settings → Secrets and variables → Actions → New repository secret, dengan nama `GEMINI_API_KEY` dan nilai berupa kunci tersebut.
   Setelah itu buka Actions → "接種資訊更新" → Run workflow untuk menjalankannya sekali secara manual (sekitar 2–5 menit); selanjutnya berjalan otomatis setiap hari pukul 06:00 Taipei time.
   Tingkat gratis tidak dikenai biaya, tetapi Google memakai konten yang dikirim untuk meningkatkan produknya (yang dikirim situs ini hanya teks publik dari situs resmi); bila peraturan instansi tidak mengizinkannya, aktifkan penagihan (billing) untuk proyek tersebut.

Tidak disarankan memakai mesin eksekusi yang di-host sendiri milik GitHub (self-hosted runner): pada repo **publik**, pull request dari siapa pun
dapat menyebabkan kode dijalankan di mesin tersebut, dan GitHub sendiri tidak menyarankan penggunaan seperti itu. Cara di atas hanya membutuhkan mesin itu "mendorong keluar" dan tidak menerima perintah dari luar.

Hal yang perlu diperhatikan saat memakai GitHub Pages: pada paket gratis, Pages memerlukan repo publik; Pages tidak dapat mengatur header HTTP,
sehingga dari header yang disarankan di bagian IIS di atas, hanya bagian yang dapat dinyatakan oleh `<meta>` di `index.html` yang berlaku (`frame-ancestors` tidak);
Pages menerapkan cache tetap sekitar 10 menit untuk semua berkas, sehingga setelah data diperbarui, pengguna baru melihatnya paling lama 10 menit kemudian.

## Cara integrasi data resmi yang disarankan

API `POST /Home/GetHospitalData` pada situs saat ini memiliki keterbatasan berikut sehingga tidak cocok dipanggil langsung dari front-end:

- Setiap panggilan hanya mengembalikan **20 entri** fasilitas kesehatan; untuk mendapatkan seluruhnya (sekitar 4.660 entri) diperlukan sekitar **280 kali** panggilan berhalaman;
- Setiap respons berukuran sekitar 390 KB dan **berisi HTML yang sudah dirender di sisi server** (bukan format data yang bersih); dihitung demikian, mengambil seluruh
  data berarti mentransfer hampir **97 MB**;
- Header `X-Requested-With: XMLHttpRequest` diperlukan agar permintaan diterima;
- **CORS tidak dibuka**, sehingga browser tidak dapat memanggilnya langsung lintas domain.

**Pendekatan yang disarankan**: di back-end (server tempat situs saat ini berjalan, atau lingkungan yang berhak mengakses basis data sumber), buat sebuah **tugas terjadwal**
yang setiap N menit (misalnya 5–15 menit, sesuai frekuensi pembaruan data) mengekspor langsung dari basis data dan menghasilkan
`hospitals.json` sesuai format `docs/DATA_SCHEMA.md` (setelah normalisasi sekitar 1,9 MB, sekitar 330 KB setelah kompresi gzip; transliterasi bahasa Inggris dapat tetap memakai `scripts/romanize.mjs`),
lalu memublikasikannya ke host berkas statis atau CDN.

Alternatif lain yang layak adalah tim situs saat ini menambahkan **endpoint JSON yang mengembalikan seluruh data** (berhalaman atau tidak boleh keduanya, tetapi CORS harus dibuka
atau di-deploy pada domain yang sama), dengan efek setara dengan ekspor terjadwal di atas.

Apa pun yang dipilih, front-end hanya perlu mengganti satu berkas, yaitu `public/js/data-source.js` (ganti `fetch('./data/hospitals.json')`
dengan panggilan ke endpoint baru, dan pastikan objek yang dikembalikan tetap sesuai struktur `{ meta, vaccines, groups, hospitals }`),
sedangkan kode lainnya sama sekali tidak perlu diubah.

## Keamanan

**Pustaka pihak ketiga** (diperiksa 2026-09-21): Leaflet 1.9.4 dan leaflet.markercluster 1.5.3 keduanya merupakan versi stabil terbaru di npm
(Leaflet 2.0 masih alpha, dan berubah menjadi ESM murni serta menghapus `L` global; markercluster belum kompatibel, sehingga upgrade belum disarankan).
Berkas di dalam `public/vendor/` identik byte demi byte dengan paket npm; `npm run verify-vendor` memverifikasinya dengan sha256, dan `npm test` juga menyertakan pemeriksaan ini.
`npm audit` menunjukkan 0 temuan. Leaflet memiliki satu advisori CVE-2025-69993 yang belum ada versi perbaikannya (`bindPopup()` merender string masukan sebagai HTML,
dan pengelola menetapkannya sebagai perilaku yang memang terdokumentasi); situs ini **tidak menggunakan** popup／tooltip, dan semua string data ditulis melalui `textContent` atau atribut, sehingga tidak terdampak.

**Perlindungan front-end**: CSP di `index.html` tidak mengizinkan skrip dan gaya inline, dan hanya membuka gambar dari dua domain peta dasar; selain itu Trusted Types diaktifkan
(`public/js/trusted-types.js`), yang hanya meloloskan string HTML tetap milik Leaflet dan `map.js`. Bila kelak HTML pin atau string
hak cipta peta dasar diubah, daftar izin pada berkas itu harus diperbarui bersamaan, atau pengujian e2e akan gagal karena galat di konsol. Tautan eksternal selalu memakai `rel="noopener noreferrer"`,
dan URL reservasi hanya menerima https. Lokasi pengguna hanya disimpan di memori, tidak ditulis ke URL, penyimpanan, maupun permintaan apa pun (namun saat peta diperbesar, server peta dasar dapat menyimpulkan perkiraan wilayah dari permintaan tile).

**Pipeline data**: respons dari situs sumber selalu dianggap tidak tepercaya. `scripts/sanitize.mjs` membangun ulang setiap bidang yang akan dipublikasikan berdasarkan daftar putih
(menghapus karakter kontrol dan karakter kontrol teks dua arah, membatasi panjang, memeriksa rentang nilai dan rentang koordinat, memeriksa format telepon dan URL);
`normalize.mjs` dan `keep-live-data.mjs` sama-sama memakainya sebagai gerbang terakhir; `harvest.mjs` menetapkan batas atas untuk satu respons, total transfer, jumlah entri per halaman, dan jumlah entri total.
Pengujian terkait ada di `tests/security.test.mjs`.
Bagian info vaksinasi diperlakukan sama: `harvest-info.mjs` memakai parser daftar putih tanpa dependensi paket yang hanya mengambil paragraf, daftar, tabel, dan tautan (script, atribut event, iframe, dan sebagainya dibuang seluruhnya),
tautan hanya dipertahankan bila https dan hostnya ada dalam daftar izin (`*.gov.tw`, `*.gov.taipei`, YouTube; lihat `docs/INFO_SCHEMA.md`); keluaran terjemahan mesin hanya dipakai bila strukturnya persis sama dengan teks asli, URL selalu diambil dari teks asli,
dan semua berkas diverifikasi oleh `scripts/sanitize-info.mjs` sebelum ditulis dan sebelum deploy (pengujian terkait ada di `tests/info.test.mjs`).

**GitHub Actions**: setiap job memakai hak akses minimum (`permissions: {}` secara bawaan; hanya deploy yang memiliki `pages: write`; hanya `info-update.yml` yang dapat menulis ke repo —
`contents: write` untuk mendorong cabang data, `actions: write` untuk memicu deploy), semua action disematkan ke SHA commit lengkap, `${{ }}` selalu diteruskan melalui `env:` dan tidak ditulis langsung ke dalam perintah,
dan checkout tidak menyimpan kredensial. Saat menaikkan versi action, verifikasi ulang dan perbarui SHA-nya (`tests/data-branch.test.mjs` memeriksa aturan-aturan ini).
Disarankan membuka Settings → Environments → github-pages pada repo dan memastikan hanya cabang `main` yang diizinkan untuk deploy.

**Kunci terjemahan dan izin menulis**: `GEMINI_API_KEY` hanya berada di secret terenkripsi GitHub, tidak keluar dari GitHub dan tidak berada di mesin dalam negeri; `info-update.yml` hanya memberikannya pada langkah "Terjemahan"
sebagai variabel lingkungan untuk `translate-info.mjs` (langkah pengambilan, verifikasi, pengiriman, dan lainnya tidak mendapatkannya); program hanya menaruhnya di header `x-goog-api-key` dan tidak pernah di URL,
dan pesan galat di log juga disamarkan lebih dulu dari kunci tersebut. Bila sumber tidak berubah dan semua bahasa sudah diterjemahkan, kunci bahkan tidak diserahkan ke program terjemahan pada langkah ini. `GITHUB_TOKEN` untuk pengiriman juga hanya diberikan pada langkah "menulis ke cabang data",
dan diteruskan ke git lewat header http, tidak ditulis ke URL atau berkas konfigurasi. Perlu diperhatikan: **`contents: write` tidak dapat dibatasi GitHub hanya ke satu cabang** (aturan proteksi cabang juga tidak dapat membatasi token ini menjadi
"hanya boleh mendorong ke data"); "hanya menulis ke cabang data" dijamin oleh prosedurnya (`scripts/push-data-branch.sh`); disarankan mengatur proteksi cabang untuk `main` (mewajibkan pull request),
agar token ini setidaknya tidak dapat langsung mengubah `main`. Pull request dari pihak luar tidak dapat memicu workflow ini (hanya jadwal dan pemicuan manual), sehingga juga tidak mendapatkan kuncinya.

**Keterbatasan GitHub Pages**: header HTTP tidak dapat diatur, sehingga tidak ada `frame-ancestors`／`X-Frame-Options` (untuk mencegah penyematan oleh situs lain).
Situs ini tidak memiliki status login atau operasi sensitif yang dapat dipancing untuk diklik, sehingga risikonya rendah; jika di-deploy ke host yang dapat mengatur header, tambahkan keduanya.

## Peta dasar

Peta dasar dipilih menurut bahasa antarmuka agar nama tempat dapat dibaca (proses evaluasi dan bukti pengujian ada di `docs/BASEMAP.md`):

- **Mandarin Tradisional**: "Peta Elektronik Versi Umum" (通用版電子地圖) `EMAP` dari Pusat Survei dan Pemetaan Nasional (NLSC) (nama tempat dalam bahasa Mandarin, dimuat lebih cepat bagi pengguna di Taiwan); bila gagal, beralih ke tile resmi OpenStreetMap.
- **Jepang**: sama seperti Mandarin Tradisional (pengguna Jepang dapat membaca kanji nama jalan, dan konsisten dengan papan nama jalan).
- **Bahasa lain** (en, ko, id, vi, th, tl): NLSC「臺灣通用電子地圖EN」`EMAP8` (nama tempat bahasa Inggris untuk seluruh Taiwan); bila gagal, beralih ke OpenStreetMap dan menampilkan pemberitahuan "nama tempat mungkin ditampilkan dalam bahasa Mandarin". Saat ini tidak ada sumber tanpa kunci API yang menyediakan nama jalan dalam bahasa Korea, sehingga ko juga memakai bahasa Inggris.

**Pengguna dapat mengganti sendiri**: di dalam legenda (di desktop pojok kiri bawah dan terbuka secara bawaan; di ponsel pojok kanan atas dan tertutup secara bawaan) terdapat tombol radio "Peta dasar": pada antarmuka Mandarin／Jepang
dapat dipilih「通用版電子地圖」dan「OpenStreetMap」; pada antarmuka bahasa asing dapat dipilih “NLSC (English)”, NLSC versi Mandarin (nama tempat konsisten dengan papan jalan), dan “OpenStreetMap”.
Peta langsung berganti saat dipilih, dan baris hak cipta ikut berganti; pilihan disimpan di localStorage browser dengan key `vaxmap.basemap`, **dengan pilihan untuk nama tempat Mandarin dan nama tempat bahasa asing disimpan terpisah**,
dan masing-masing diterapkan saat bahasa diganti. Bila peta dasar yang dipilih gagal dimuat, sistem tetap otomatis beralih ke peta berikutnya dan menampilkan pemberitahuan, dan tombol radio juga berpindah ke peta dasar yang benar-benar ditampilkan.

Saat bahasa diganti, peta dasar langsung berganti tanpa memuat ulang halaman. Urutannya ditentukan oleh `BASEMAP_CHAINS` di `public/js/map.js` (item pertama pada setiap rantai adalah bawaan,
dan sisanya berurutan sebagai cadangan; layer dari host yang sama dianggap gagal bersama-sama); `img-src` pada CSP di `index.html` hanya membuka kedua domain ini (EMAP8 dan EMAP berada pada host yang sama). Saat pengujian, tambahkan pada URL
`?tiles=nlsc`／`?tiles=osm`／`?tiles=nlscEn` untuk menentukan peta dasar awal (harus berada dalam rantai bahasa saat ini), tambahkan `?tiles=fail` untuk mensimulasikan kegagalan peta dasar bawaan,
atau tambahkan penulisan seperti `?tiles=fail:osm` untuk membuat hanya peta dasar yang ditentukan yang gagal.
**Sebelum diluncurkan secara resmi**, pastikan untuk:

- Memastikan [kebijakan penggunaan tile OSM](https://operations.osmfoundation.org/policies/tiles/). Server tile resmi OSM
  dioperasikan dari donasi dan tidak menjamin ketersediaan; kebijakannya secara tegas menyatakan bahwa penggunaan dengan lalu lintas besar tidak boleh bergantung padanya, dan pelanggaran dapat diblokir tanpa pemberitahuan.
  Untuk prototipe dan demo berlalu lintas rendah tidak ada masalah; bila akan dijadikan peta dasar bawaan layanan publik resmi, disarankan beralih ke tile yang dihosting sendiri atau penyedia tile komersial
  (MapTiler, Stadia, Mapbox, dan sebagainya, yang sebagian besar tetap memakai data OSM). Saat ini bawaan untuk semua bahasa adalah NLSC, dan OSM hanya dipakai sebagai cadangan atau bila dipilih sendiri oleh pengguna;
- Untuk WMTS NLSC, keterangan resminya menyebut "pengguna tidak perlu mengajukan permohonan" untuk menghubungkannya, tetapi tidak ada batas lalu lintas atau tingkat layanan yang dipublikasikan; peta dasar bawaan semua bahasa berada di NLSC (EMAP／EMAP8),
  sehingga sebelum peluncuran resmi dan sebelum lalu lintas membesar, disarankan mengonfirmasinya kepada Pusat Survei dan Pemetaan Nasional (NLSC) atas nama Taiwan CDC (lihat `docs/BASEMAP.md`).

## Dukungan browser

Memakai API browser modern (`fetch`, ES modules, CSS Grid, `<details>`, `prefers-color-scheme`),
dengan target Chrome, Edge, Firefox, dan Safari (termasuk iOS Safari) dalam dua tahun terakhir. IE11 tidak didukung, dan tidak ada polyfill terkait.

## Keterbatasan yang diketahui

- Data berupa snapshot (diperbarui dua kali sehari), bukan real-time; sebelum vaksinasi, selalu hubungi fasilitas kesehatan melalui telepon untuk memastikan.
- Jam praktik (pagi／siang／malam) dinyatakan dengan bitmask yang dikonversi dari data Administrasi Asuransi Kesehatan Nasional (中央健保署), hanya berupa perkiraan waktu, bukan jadwal poliklinik yang presisi.
- Nama dan alamat fasilitas kesehatan mempertahankan teks asli dari sumber (misalnya「台北長庚紀念醫院」adalah nama resminya); hanya kolom kabupaten／kota dan distrik yang diseragamkan menjadi「臺」.
- Nama fasilitas dalam bahasa Inggris adalah transliterasi mesin (nama orang dirangkai dengan pinyin, dan hanya sekitar 25 rumah sakit terkenal yang memakai nama Inggris resminya), bukan terjemahan resmi;
  alamat bahasa Inggris dihasilkan menurut format kantor pos dan hanya menyimpan nomor rumah pertama.
- Teks antarmuka enam bahasa asing (ja, ko, id, vi, th, tl) adalah draf awal AI; sebelum dipublikasikan secara resmi, sebaiknya ditinjau oleh penutur asli.
- Status seperti lokasi dan rentang peta tidak ditulis ke URL yang dapat dibagikan (URL hash); hanya kondisi filter dan fasilitas yang dipilih yang dibagikan.
- IE／WebView Android lama belum diuji; tile peta dapat gagal dimuat pada lingkungan jaringan yang tidak stabil (tersedia cadangan otomatis dan pergantian peta dasar secara manual).
