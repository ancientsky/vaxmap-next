# 백신 및 인플루엔자 치료제 지도（vaxmap-next）

**語言／Language：** [繁體中文](README.md) ・ [English](README.en.md) ・ [日本語](README.ja.md) ・ 한국어 ・ [Bahasa Indonesia](README.id.md) ・ [Tiếng Việt](README.vi.md) ・ [ไทย](README.th.md) ・ [Filipino](README.tl.md)

이 프로젝트는 위생복리부 질병관제서(Taiwan CDC)의 「백신 및 인플루엔자 항바이러스제 지도」(vaxmap.cdc.gov.tw)를 위한 **콘셉트 프로토타입(Proof of Concept)**으로,
현행 웹사이트보다 더 빠르고 사용하기 편한 프런트엔드 경험을 시연하기 위해 만들었습니다. **공식 웹사이트가 아니며** 어떤 정부 도메인에도 배포되어 있지 않고, 데이터도
**실시간 데이터가 아닙니다.** 현행 사이트에서 하루 두 번 수집한 스냅샷입니다(최초 스냅샷은 2026-09-21이며, 갱신 방식은 「데이터 갱신 방법」과 「GitHub Pages에 배포하기」를 참고하십시오). 이 프로젝트를 인수하셨다면
먼저 `docs/DATA_SCHEMA.md`(프런트엔드 데이터 계약)와 `docs/HARVEST.md`(스냅샷을 어떻게 얻었고 어떤 제약이 있는지)를 읽으시기 바랍니다.

## 이 프로젝트가 무엇이고 무엇이 아닌지

- 맞는 것: 단일 JSON 파일만 읽어 동작하는 순수 정적 웹사이트 프로토타입으로, 새로운 필터, 목록, 지도 인터랙션, 공유 가능한 URL 설계를 보여 줍니다.
- 아닌 것: 정식 서비스 시스템, 실시간 데이터 소스, 또는 현행 사이트의 대체물이 아닙니다. 거리, 재고, 진료 시간대는 모두 스냅샷 시점의 데이터이므로
  **실제 접종 전에는 반드시 의료기관에 먼저 전화로 확인하십시오.**

## 폴더 구조

```

  index.html
  css/app.css
  js/
    app.js              Main flow / state management / view assembly
    ui.js               DOM builders (pure functions, no business logic)
    map.js              Leaflet map wrapper
    logic.js            Pure functions (time, filtering, sorting, URL state) - no DOM dependency, unit-testable
    i18n.js             Multilingual support: locale detection, string lookup, locale switching (see docs/I18N.md)
    data-source.js       Data source adapter (currently reads local JSON; switching to a live API only changes this file)
  data/hospitals.json   Normalized facility data (the only data file the front end reads)
  i18n/<lang>.json      UI strings (zh-Hant source text, en, ja, ko, id, vi, th, tl)
  vendor/leaflet, vendor/markercluster   Third-party map libraries (bundled static files, deployed together with public/)

data/raw/               Raw harvest files (.json.gz), used only to generate public/data/hospitals.json, not deployed with the site
data/districts-en.json  Official English names of the 22 counties/cities and 369 districts (used by romanize.mjs, not generated by pinyin)
scripts/
  dev-server.mjs        Zero-dependency static server for local development
  harvest.mjs           Harvests nationwide facility data from the current site → data/raw/*.json.gz (interim approach, see docs/HARVEST.md)
  normalize.mjs         Conversion script: data/raw/*.json.gz → public/data/hospitals.json
  romanize.mjs          English (Latin-alphabet) transliteration of facility names / addresses / districts, called by normalize.mjs
  keep-live-data.mjs    At deploy time, uses the newer data from the data branch (or the live site), sanitizing it first (used by GitHub Actions)
  publish-data.sh       Runs on a machine in Taiwan: harvest → check → push to the data branch → trigger deployment
  install-updater.sh    Installs a daily schedule on a Linux machine in Taiwan (systemd user timer)
.github/workflows/
  deploy.yml            Deploys to GitHub Pages (site from main, data from the data branch)
  freshness.yml         Checks daily whether the data has gone more than 36 hours without an update, and sends an email if it is too old
docs/
  DATA_SCHEMA.md        Format contract for public/data/hospitals.json
  HARVEST.md            How the 2026-09-21 snapshot was harvested, and known limitations
  I18N.md               Localization rules, medical terminology glossary, full key list (for translators)
  BASEMAP.md            Evaluation of basemap place-name languages, measured evidence and decisions
tests/
  logic.test.mjs        Unit tests for logic.js (node:test)
  i18n.test.mjs         Locale file consistency (keys, parameters, placeholder files)
  data.test.mjs         Data quality tests for hospitals.json, cross-validated against data/raw
  e2e.spec.mjs          Playwright end-to-end smoke tests (desktop + mobile)
  a11y.spec.mjs         Accessibility checks (report only, no fixes)
  harvest.test.mjs      Verifies harvest.mjs against a mock source server (mock-source.mjs)
  romanize.test.mjs     Hand-checked examples of English transliteration (names, addresses, edge cases)
```

## 로컬 실행

개발 서버는 기본적으로 로컬 호스트(127.0.0.1)에만 바인딩됩니다. 같은 네트워크의 휴대폰에서 접속해 테스트하려면 `HOST=0.0.0.0 npm run dev`로 실행하십시오.

요구 사항: Node.js 18 이상(`"type": "module"`, ES modules와 `node:test` 사용). 이 프로젝트에는 **빌드 과정이 없습니다.**
`public/` 아래의 파일이 그대로 배포 가능한 결과물이며, `leaflet`／`leaflet.markercluster`는 `devDependencies`에만 나열되어 있습니다.
이는 나중에 `public/vendor/` 아래의 번들 파일을 다시 생성할 때 쓰기 위한 것이므로, 운영 환경에서는 `npm install`이 필요하지 않습니다.
유일한 예외는 **데이터 생성**입니다. `scripts/normalize.mjs`는 `pinyin-pro`(devDependency, 로컬 사전을 사용하며 네트워크에 연결하지 않음)로 영문 표기를 생성하므로,
`npm run normalize`／`update-data`를 실행하기 전에 먼저 `npm install`을 해야 합니다(`publish-data.sh`는 패키지가 없으면 자동으로 `npm ci`를 실행합니다).

```bash
npm run dev        # Start http://localhost:5173/ (override with the PORT environment variable)
```

## 테스트 실행

```bash
npm test           # Unit tests + data quality tests (node --test)
npm run test:e2e   # Playwright end-to-end smoke tests (desktop 1440x900, mobile 390x844)
npm run test:a11y  # Accessibility checks (reports issues only, never modifies any file)
```

`test:e2e`와 `test:a11y`를 실행하려면 환경에 `playwright`가 전역으로 설치되어 있어야 하고(이 프로젝트는 버전 1.56을 가정합니다) 브라우저도 미리 설치되어 있어야 합니다
(`PLAYWRIGHT_BROWSERS_PATH`가 Chromium이 설치된 디렉터리를 가리켜야 합니다). 이 두 스크립트는 스스로
`scripts/dev-server.mjs`를 임의의 사용 가능한 포트에서 띄우고 테스트가 끝나면 자동으로 종료하므로, **서버를 따로 수동으로 시작할 필요가 없습니다.**

## 배포

`public/`이 유일하게 서비스에 올려야 하는 디렉터리이며, 어떤 정적 호스트(Nginx, IIS, S3+CDN, GitHub Pages 등)에 복사해도 됩니다.
서버 측 프로그램이나 데이터베이스는 필요하지 않습니다.

### IIS 배포 시 유의 사항

- **MIME 타입**: `.json`이 `application/json`에 매핑되어 있는지 확인하십시오(IIS 기본 설정에 보통 이미 들어 있으며, 없으면
  `web.config`에 `<staticContent><mimeMap fileExtension=".json" mimeType="application/json" /></staticContent>`를 추가합니다).
- **정적 압축**: IIS의 Static Compression(`httpCompression`／`urlCompression`)을 활성화하십시오.
  `hospitals.json`은 압축하지 않으면 약 1.9 MB이지만 gzip을 켜면 약 330 KB로 줄어들어, 모바일 네트워크 사용자 경험에 큰 영향을 줍니다.
- **권장 HTTP 헤더**:
  | 헤더 | 권장 값 | 이유 |
  |---|---|---|
  | `Content-Security-Policy` | `public/index.html`에 이미 있는 `<meta http-equiv>` 설정을 서버 계층에 동일하게 반영(`frame-ancestors 'none'`은 HTTP 헤더 계층에서 설정해야 하며, `<meta>` 태그로는 `frame-ancestors`를 선언할 수 없음) | iframe 삽입(clickjacking) 방지, 스크립트／스타일 출처 제한 |
  | `X-Content-Type-Options` | `nosniff` | 브라우저가 MIME 타입을 추측하면서 생기는 위험 방지 |
  | `Referrer-Policy` | `strict-origin-when-cross-origin` | 이미 `<meta name="referrer">`로 설정되어 있으며, 서버 계층에서 한 겹 더 추가할 수 있음 |
  | `X-Frame-Options` | `DENY`(CSP `frame-ancestors`를 사용하지 않는 경우) | 위와 같은 이유이며, 구형 브라우저를 위한 보험 |
- **캐시 전략**:
  | 경로 | 권장 캐시 | 이유 |
  |---|---|---|
  | `data/hospitals.json` | 짧은 캐시(예: `Cache-Control: no-cache` 또는 `max-age=60~300`) | 데이터가 주기적으로 갱신되므로, 캐시가 너무 길면 사용자가 오래된 재고를 보게 됨 |
  | `vendor/**`、`css/**`、`js/**` | 긴 캐시＋버전 관리(예: `max-age=31536000, immutable`, 파일명 또는 쿼리 문자열에 버전 번호 추가) | 내용이 바뀔 때만 무효화하면 되므로 중복 다운로드를 크게 줄일 수 있음 |
  | `index.html` | 짧은 캐시 또는 캐시 안 함 | 사용자가 최신 리소스 참조를 받도록 보장 |

  현재 `scripts/dev-server.mjs`(로컬 개발 전용)는 모든 파일에 `Cache-Control: no-cache`를 응답합니다. 운영 환경에서는
  위 표에 따라 IIS／CDN 계층에서 별도로 설정하십시오. `public/`의 내용 자체를 수정할 필요는 없습니다.

## 데이터 갱신 방법(현재 방식)

`npm run update-data`는 세 가지 작업을 순서대로 실행합니다. `scripts/harvest.mjs`가 현행 사이트에서 전국 의료기관 데이터를 수집해
`data/raw/vaxmap_raw_YYYYMMDD-HHmm.json.gz`로 저장하고, `scripts/normalize.mjs`가 가장 최근의 원본 파일을
`public/data/hospitals.json`으로 변환하며(형식 계약은 `docs/DATA_SCHEMA.md` 참고), 마지막으로 데이터 검사를 실행합니다. 어느 단계든 실패하면 중단되며,
반쪽짜리 데이터가 서비스에 올라가는 일은 없습니다. 수집의 세부 사항과 제약은 `docs/HARVEST.md`를 참고하십시오.

전체 수집 한 번에 현행 사이트로 약 280건의 요청이 나가고 100 MB에 가까운 데이터가 전송되며, 10–15분이 걸립니다. 원본 데이터 자체는 의료기관이 매일 보고하는 것이므로
**하루 1–2회 갱신이면 충분하며, 빈도를 높이거나 요청 간격을 줄이지 마십시오.** 현행 사이트는 해외 접속을 받지 않으므로 수집은 국내 머신에서 실행해야 합니다. GitHub Pages와 함께 쓰는 자동 갱신 방식은 다음 절을 참고하십시오.

이것은 여전히 **과도기적 방식**이며, 정식 방식은 서버 측에서 데이터를 직접 내보내는 것입니다(「권장하는 정식 데이터 연동 방식」 참고).

## 다국어 지원

인터페이스는 번체 중국어(기본), English, 日本語, 한국어, Bahasa Indonesia, Tiếng Việt, ไทย, Filipino를 지원하며,
헤더의 지구 아이콘 메뉴로 전환합니다(페이지를 다시 불러오지 않음). 언어는 URL의 `#lang=en`, 마지막으로 선택한 값(localStorage),
브라우저 언어 순으로 결정되며, 모두 없으면 번체 중국어가 됩니다. 기본 언어가 아니면 공유 가능한 URL에 기록됩니다. 시·현 이름은 번역되며, 외국어 시·현 이름으로도 검색할 수 있습니다(예: “Taipei”).

**의료기관 이름과 주소의 영문 표기**: `hospitals.json`의 각 의료기관 항목에는 `nameEn`、`addrEn`、`cityEn`、`distEn`이 별도로 있습니다
(`scripts/romanize.mjs`가 규칙으로 생성합니다. 의료 용어는 어휘표를 조회해 영어로 옮기고, 고유명사는 한어병음을 쓰며, 시·현과 행정구는 공식 영문명을 쓰고,
주소는 우체국 영문 표기 순서를 따릅니다. 예: 「林文正耳鼻喉科診所」→ “Linwenzheng ENT Clinic”、「臺北市北投區明德路92號1樓」→
“1F, No. 92, Mingde Rd., Beitou District, Taipei City”). 언어 파일의 `meta.script`가 표시 방식을 결정합니다. `latin`(en、ko、id、vi、th、tl)은
영문을 위주로 하고 중국어 원문을 둘째 줄에 두며(택시 기사나 접수 창구에 보여 주기 편함), `han`(번체 중국어, 일본어)은 중국어를 위주로 하되 일본어에는 영문 이름을 덧붙입니다.
검색은 어떤 언어에서든 중국어와 영문 필드를 동시에 비교합니다(“Beitou”、“Mingde”、“ENT”、“Lin Wen Zheng” 모두 찾을 수 있습니다). 표기는 기계적 규칙으로 생성되며
공식 번역명이 아니므로, 일부 이름이나 주소는 완전히 정확하지 않을 수 있습니다.

- **문자열 위치**: `public/i18n/<lang>.json`, 평평한(flat) key → 문자열 구조이며 `zh-Hant.json`이 원문입니다.
- **key 규칙**: 기능별 네임스페이스로 이름을 붙입니다(`filters.today`、`detail.call`、`status.ok.text`). `{n}` 같은 매개변수는 반드시 유지해야 하고,
  수량이 정확히 1일 때는 `<key>.one`을 사용하며, HTML을 포함해서는 안 됩니다. 모든 언어 파일은 번체 중국어와 key가 완전히 같아야 합니다(`npm test`가 검사합니다).
- **언어 추가**: `logic.js`의 `SUPPORTED_LANGS`에 코드 추가 → `en.json`을 복사해 `meta.*` 수정, `"_status": "placeholder"` 설정
  → `index.html`의 `#lang-select`에 옵션 추가 → `npm test`. 자세한 절차와 의료 용어 대조표는 `docs/I18N.md`를 참고하십시오.
- **검수 상태**(파일 내 `_status`): `zh-Hant`는 원문, `en`은 완료, `ja`、`ko`、`id`、`vi`、`th`、`tl`은
  `placeholder`입니다(임시로 영어로 표시되며 번역 대기 중).

## GitHub Pages에 배포하기(매일 자동 데이터 갱신 포함)

**중요한 전제: 질병관제서의 현행 사이트는 해외 접속을 받지 않습니다.** 2026-09-21 실측 결과, GitHub Actions의 실행 머신(해외에 위치)에서
`vaxmap.cdc.gov.tw`에 연결하면 연결 시간이 초과되었습니다(`UND_ERR_CONNECT_TIMEOUT`). 따라서 데이터 수집을 GitHub에서 실행할 수 없어,
「국내 머신에서 수집하고 GitHub은 배포만 담당」하는 방식으로 바꾸었습니다.

```
Linux machine in Taiwan (daily at 05:30, 12:30)  GitHub
  scripts/publish-data.sh                          
    ├─ harvest.mjs harvest → normalize.mjs → data checks  
    ├─ force-push hospitals.json to the data branch  ──►  data branch (always a single commit, so the repo does not grow)
    └─ gh workflow run deploy.yml             ──►  deploy.yml: take the site from main + the newer data from the data branch
                                                    → run sanitizing and checks again → deploy to Pages
```

`.github/workflows/deploy.yml`은 `main`에 푸시되거나 수동으로／`publish-data.sh`에 의해 트리거될 때 실행됩니다. `data` 브랜치의
`hospitals.json`을 가져와 `scripts/keep-live-data.mjs --file`로 정리하고 `main`에 있는 스냅샷보다 최신임을 확인한 경우에만 채택하며, `data`
브랜치가 없으면 `main`에 있는 스냅샷을 그대로 씁니다. `.github/workflows/freshness.yml`은 매일 Taipei time (UTC+8) 09:00에 `data` 브랜치의 데이터를 점검하여
36시간 넘게 갱신되지 않았으면 해당 실행을 실패 처리하고, GitHub이 repo 소유자에게 메일로 알립니다(수집 머신이 동작하지 않거나 계속 실패하고 있다는 뜻입니다).
웹사이트 화면의 「데이터 스냅샷」에도 「N일째 갱신되지 않음」이 표시됩니다.

최초 설정:

1. GitHub에 공개 repo를 만들고 이 프로젝트를 푸시합니다(기본 브랜치는 `main`이어야 합니다).
2. repo의 Settings → Pages로 가서 Source를 **GitHub Actions**로 설정한 다음, 「배포」 워크플로를 한 번 다시 실행합니다.
3. **국내에 있고 현행 사이트에 접속할 수 있는** Linux 머신(git, Node.js 20 이상, `gh auth login`을 마친 GitHub CLI가 필요합니다)에서
   프로젝트 폴더로 이동해 먼저 수동으로 한 번 시험합니다: `npm run publish-data`. 성공하면 10–15분 뒤 웹사이트의 스냅샷 시각이 갱신됩니다.
4. `scripts/install-updater.sh`를 실행해 매일 스케줄을 설치합니다. 이 스크립트는 전용 폴더를 별도로 만들고
   (`~/.local/share/vaxmap-updater`, 코드를 수정하는 폴더와 분리되어 있으며 매 실행 전에 `main`을 자동으로 동기화합니다),
   systemd 사용자 타이머를 설정합니다. 전원이 꺼져 있어 놓친 스케줄은 부팅 후 보충 실행됩니다. 제거하려면 `scripts/install-updater.sh --uninstall`을 사용하십시오.

GitHub의 자체 호스팅 실행 머신(self-hosted runner)으로 바꾸는 것은 권장하지 않습니다. **공개** repo에서는 누구든 보낸 pull request가
그 머신에서 코드를 실행하게 만들 수 있으며, GitHub 공식 문서도 이런 사용을 권장하지 않습니다. 위의 방식은 그 머신이 「밖으로 푸시」하기만 하면 되고, 외부의 어떤 명령도 받지 않습니다.

GitHub Pages를 사용할 때 유의할 점: 무료 요금제의 Pages는 공개 repo가 필요합니다. Pages는 HTTP 헤더를 사용자 정의할 수 없으므로
위 IIS 절에서 권장한 헤더 가운데 `index.html`의 `<meta>`로 표현할 수 있는 부분만 적용됩니다(`frame-ancestors`는 적용되지 않습니다).
Pages는 모든 파일에 고정적으로 약 10분간 캐시를 적용하므로, 데이터가 갱신된 뒤 사용자에게 보이기까지 최대 10분이 걸립니다.

## 권장하는 정식 데이터 연동 방식

현행 사이트의 `POST /Home/GetHospitalData` API에는 다음과 같은 제약이 있어 프런트엔드가 직접 호출하기에 적합하지 않습니다.

- 호출 한 번에 의료기관 데이터를 **20건**만 반환하므로, 전체 약 4,660건을 얻으려면 약 **280번**의 페이지 호출이 필요합니다.
- 응답 하나가 약 390 KB이고 **서버 측에서 렌더링된 HTML이 들어 있어**(깔끔한 데이터 형식이 아님), 전체 데이터를
  가져오려면 **97 MB**에 가까운 양을 전송해야 합니다.
- `X-Requested-With: XMLHttpRequest` 헤더를 붙여야 요청이 받아들여집니다.
- **CORS가 열려 있지 않아** 브라우저 측에서 다른 도메인으로 직접 호출할 수 없습니다.

**권장 방안**: 백엔드(현행 사이트가 있는 서버 또는 원본 데이터베이스에 접근 권한이 있는 환경)에 **스케줄 작업**을 만들어
N분마다(예: 5–15분, 데이터 갱신 빈도에 따라 결정) 데이터베이스에서 직접 내보내고, `docs/DATA_SCHEMA.md` 형식에 맞는
`hospitals.json`을 출력하여(정규화 후 약 1.9 MB, gzip 압축 후 약 330 KB이며, 영문 표기는 `scripts/romanize.mjs`를 그대로 쓸 수 있습니다)
정적 파일 호스트나 CDN에 게시합니다.

또 다른 실행 가능한 방안은 현행 사이트 팀이 **전체 데이터를 반환하는 JSON 엔드포인트**를 새로 추가하는 것입니다(페이지 분할 여부는 상관없으나 CORS를 열거나
같은 도메인에 배포해야 합니다). 효과는 위의 스케줄 내보내기와 같습니다.

어느 방식을 택하든 프런트엔드에서는 `public/js/data-source.js` 파일 하나만 바꾸면 됩니다(`fetch('./data/hospitals.json')`을
새 엔드포인트 호출로 바꾸고, 반환되는 객체가 여전히 `{ meta, vaccines, groups, hospitals }` 구조를 따르도록 하십시오).
나머지 코드는 전혀 수정할 필요가 없습니다.

## 보안

**서드파티 라이브러리**(2026-09-21 점검): Leaflet 1.9.4와 leaflet.markercluster 1.5.3은 모두 npm의 최신 안정 버전입니다
(Leaflet 2.0은 아직 alpha이고, 순수 ESM으로 바뀌면서 전역 `L`이 제거되었으며, markercluster가 아직 호환되지 않으므로 당분간 업그레이드를 권장하지 않습니다).
`public/vendor/` 안의 파일은 npm 패키지와 바이트 단위로 동일하며, `npm run verify-vendor`가 sha256으로 검증하고 `npm test`에도 이 검사가 포함되어 있습니다.
`npm audit` 결과는 0건입니다. Leaflet에는 아직 수정 버전이 없는 CVE-2025-69993 보고가 있습니다(`bindPopup()`이 전달받은 문자열을 HTML로 렌더링하는 문제로,
유지 관리자는 문서에 기재된 기존 동작으로 판단했습니다). 이 사이트는 popup／tooltip을 **사용하지 않으며**, 모든 데이터 문자열을 `textContent` 또는 속성으로 기록하므로 영향을 받지 않습니다.

**프런트엔드 방어**: `index.html`의 CSP는 인라인 스크립트와 스타일을 허용하지 않고 이미지는 두 개의 베이스맵 도메인만 허용합니다. 또한 Trusted Types를 활성화하여
(`public/js/trusted-types.js`) Leaflet과 `map.js`의 고정 HTML 문자열만 통과시킵니다. 나중에 핀의 HTML이나 베이스맵의
저작권 문자열을 수정하면 반드시 이 파일의 허용 목록도 함께 갱신해야 하며, 그렇지 않으면 e2e 테스트가 콘솔 오류로 실패합니다. 외부 링크는 예외 없이 `rel="noopener noreferrer"`를 쓰고,
예약 URL은 https만 받습니다. 사용자의 위치는 메모리에만 존재하며 URL, 저장소, 어떤 요청에도 기록되지 않습니다(다만 지도를 확대하면 베이스맵 서버가 타일 요청으로 대략적인 지역을 추정할 수 있습니다).

**데이터 파이프라인**: 원본 사이트의 응답은 항상 신뢰할 수 없는 것으로 취급합니다. `scripts/sanitize.mjs`는 화이트리스트로 게시할 각 필드를 다시 구성하며
(제어 문자와 양방향 텍스트 제어 문자 제거, 길이 제한, 수치 범위와 좌표 범위 검사, 전화번호와 URL 형식 검사),
`normalize.mjs`와 `keep-live-data.mjs`가 모두 이를 마지막 관문으로 사용합니다. `harvest.mjs`는 단일 응답, 총 전송량, 페이지당 건수, 총 건수에 모두 상한을 두고 있습니다.
관련 테스트는 `tests/security.test.mjs`에 있습니다.

**GitHub Actions**: 각 작업은 최소 권한으로 구성했으며(deploy만 `pages: write`를 갖고, repo에 쓸 수 있는 작업은 없습니다),
모든 action은 전체 commit SHA로 고정했고, `${{ }}`는 항상 `env:`를 통해 전달하고 명령에 직접 쓰지 않으며, checkout은 자격 증명을 유지하지 않습니다.
action 버전을 올릴 때는 다시 확인하여 SHA를 갱신하십시오. repo의 Settings → Environments → github-pages에서 `main` 브랜치만 배포할 수 있도록 되어 있는지 확인하시기 바랍니다.

**GitHub Pages의 제약**: HTTP 헤더를 설정할 수 없으므로 `frame-ancestors`／`X-Frame-Options`(다른 사이트에 삽입되는 것을 방지)가 없습니다.
이 사이트에는 로그인 상태나 클릭을 유도당할 수 있는 민감한 동작이 없어 위험이 낮습니다. 헤더를 설정할 수 있는 호스트로 옮겨 배포한다면 이를 보완하십시오.

## 베이스맵

베이스맵은 인터페이스 언어에 따라 선택되어, 지명을 읽을 수 있게 합니다(평가 과정과 실측 근거는 `docs/BASEMAP.md` 참고).

- **번체 중국어**: 국토측량센터(NLSC)의 NLSC 지도 「통용판 전자지도(通用版電子地圖)」 `EMAP`(중국어 지명, 대만 사용자에게 더 빨리 로드됨). 실패하면 OpenStreetMap 공식 타일로 전환합니다.
- **일본어**: 번체 중국어와 같습니다(일본어 사용자는 한자 도로명을 읽을 수 있고 도로 표지판과도 일치하기 때문).
- **그 밖의 언어**(en、ko、id、vi、th、tl): NLSC 「臺灣通用電子地圖EN」 `EMAP8`(대만 전역 영문 지명). 실패하면 OpenStreetMap으로 전환하고 「지명이 중국어로 표시될 수 있음」이라는 안내를 표시합니다. 현재 API 키 없이 쓸 수 있는 소스 중 한국어 도로명을 제공하는 곳이 없으므로 ko도 영어를 사용합니다.

**사용자가 직접 전환 가능**: 범례(데스크톱은 왼쪽 아래에 기본 펼침, 모바일은 오른쪽 위에 기본 접힘) 안에 「베이스맵」 라디오 버튼이 있습니다. 중국어／일본어 인터페이스에서는
「통용판 전자지도」와 「OpenStreetMap」을, 외국어 인터페이스에서는 “NLSC (English)”, NLSC 중국어판(지명과 도로 표지판이 일치)과 “OpenStreetMap”을 고를 수 있습니다.
선택하면 즉시 지도가 바뀌고 저작권 표시줄도 함께 바뀝니다. 선택 값은 브라우저 localStorage의 `vaxmap.basemap`에 기록되며, **중국어 지명 계열과 외국어 지명 계열을 따로 기록하여**
언어를 전환할 때 각각 적용합니다. 선택한 베이스맵의 로드가 실패하면 여전히 자동으로 다음 것으로 전환하고 안내를 표시하며, 라디오 버튼도 실제로 표시되는 베이스맵으로 바뀝니다.

언어를 전환하면 베이스맵이 즉시 바뀌며 페이지를 다시 불러오지 않습니다. 순서는 `public/js/map.js`의 `BASEMAP_CHAINS`가 결정합니다(각 체인의 첫 번째가 기본값이고,
그 뒤가 순서대로 예비이며, 같은 호스트의 레이어는 함께 실패한 것으로 간주합니다). `index.html`의 CSP `img-src`는 이 두 도메인만 허용합니다(EMAP8과 EMAP는 같은 호스트). 테스트할 때는 URL에
`?tiles=nlsc`／`?tiles=osm`／`?tiles=nlscEn`을 붙여 시작 베이스맵을 지정할 수 있고(현재 언어의 체인 안에 있어야 함), `?tiles=fail`을 붙이면 기본 베이스맵의 실패를 시뮬레이션하며,
`?tiles=fail:osm` 같은 형태로 지정한 베이스맵만 실패시킬 수도 있습니다.
**정식 서비스 전에** 반드시 다음을 하십시오.

- [OSM 타일 사용 정책](https://operations.osmfoundation.org/policies/tiles/)을 확인하십시오. OSM 공식 타일 서버는
  기부로 운영되고 가용성을 보장하지 않으며, 정책에 대량 트래픽 용도로는 여기에 의존하면 안 된다고 명시되어 있어 위반 시 예고 없이 차단될 수 있습니다.
  프로토타입과 소규모 트래픽의 시연에는 문제가 없습니다. 정식 대외 서비스의 기본 베이스맵으로 쓰려면 자체 구축한 타일이나 상용 타일 공급자
  (MapTiler, Stadia, Mapbox 등, 대부분 여전히 OSM 데이터로 제작)로 바꾸기를 권장합니다. 현재 각 언어의 기본값은 모두 NLSC이며, OSM은 예비 또는 사용자가 직접 선택했을 때만 사용됩니다.
- NLSC의 WMTS 공식 설명은 「사용자가 신청할 필요 없이」 연동할 수 있다고 되어 있지만, 공개된 트래픽 상한이나 서비스 수준은 없습니다. 각 언어의 기본 베이스맵이 모두 NLSC(EMAP／EMAP8)에 있으므로,
  정식 서비스를 시작하고 트래픽이 커지기 전에 질병관제서 명의로 국토측량센터에 확인하는 것이 좋습니다(`docs/BASEMAP.md` 참고).

## 브라우저 지원

최신 브라우저 API(`fetch`、ES modules、CSS Grid、`<details>`、`prefers-color-scheme`)를 사용하며,
최근 2년 이내의 Chrome, Edge, Firefox, Safari(iOS Safari 포함)를 대상으로 합니다. IE11은 지원하지 않으며 관련 polyfill도 적용하지 않았습니다.

## 알려진 제약

- 데이터는 스냅샷(하루 두 번 갱신)이며 실시간이 아닙니다. 접종 전에는 반드시 먼저 의료기관에 전화로 확인하십시오.
- 진료 시간대는 중앙건강보험서(National Health Insurance Administration) 데이터를 환산한 비트마스크로 오전／오후／저녁을 나타내며, 근사적인 시간대일 뿐 정확한 진료 시간표가 아닙니다.
- 의료기관 이름과 주소는 원본의 원문을 그대로 유지합니다(예: 「台北長庚紀念醫院」이 정식 명칭입니다). 시·현과 행정구 필드만 「臺」로 통일했습니다.
- 영문 의료기관 이름은 기계적 표기입니다(사람 이름은 병음을 붙여 쓰고, 공식 영문명을 쓰는 곳은 유명 병원 약 25곳뿐). 공식 번역명이 아니며,
  영문 주소는 우체국 형식으로 생성하고 첫 번째 번지만 남깁니다.
- 여섯 가지 외국어(ja、ko、id、vi、th、tl)의 인터페이스 문구는 AI 초안이므로, 정식으로 대외 공개하기 전에 원어민의 검수를 받아야 합니다.
- 위치, 지도 범위 등의 상태는 공유 가능한 URL(URL hash)에 기록되지 않으며, 필터 조건과 선택한 의료기관만 공유됩니다.
- IE／구형 Android WebView는 아직 실측하지 않았습니다. 네트워크가 불안정한 환경에서는 지도 타일 로드가 실패할 수 있습니다(자동 예비 전환과 수동 베이스맵 전환이 있습니다).

## 현행 사이트와의 차이

| 현행 사이트의 문제 | 이 프로토타입의 방식 |
|---|---|
