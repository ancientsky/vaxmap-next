# 疫苗及流感藥劑地圖（vaxmap-next）

**語言／Language：** [繁體中文](README.md) ・ [English](README.en.md) ・ [日本語](README.ja.md) ・ [한국어](README.ko.md) ・ [Bahasa Indonesia](README.id.md) ・ Tiếng Việt ・ [ไทย](README.th.md) ・ [Filipino](README.tl.md)

Đây là **bản mẫu khái niệm (Proof of Concept)** của "Bản đồ vắc-xin và thuốc kháng vi-rút cúm" (vaxmap.cdc.gov.tw) thuộc Cục Kiểm soát Dịch bệnh, Bộ Y tế và Phúc lợi Đài Loan (Taiwan CDC),
nhằm minh họa một trải nghiệm giao diện người dùng nhanh hơn và dễ dùng hơn so với website hiện hành. **Đây không phải website chính thức**, không được triển khai trên bất kỳ tên miền chính phủ nào, và dữ liệu
**không phải dữ liệu thời gian thực** mà là ảnh chụp nhanh (snapshot) được lấy từ website hiện hành hai lần mỗi ngày (snapshot đầu tiên: 2026-09-21; cơ chế cập nhật xem các mục "Dữ liệu được cập nhật như thế nào" và "Triển khai lên GitHub Pages"). Nếu tiếp nhận dự án này,
bạn nên đọc trước `docs/DATA_SCHEMA.md` (hợp đồng dữ liệu phía front-end) và `docs/HARVEST.md` (snapshot được lấy như thế nào và có những hạn chế gì).

## Đây là gì và không phải là gì

- Là: một bản mẫu website tĩnh thuần túy, chỉ cần đọc một tệp JSON duy nhất là chạy được, trình bày thiết kế mới về bộ lọc, danh sách, tương tác bản đồ và URL có thể chia sẻ.
- Không phải: hệ thống vận hành chính thức, nguồn dữ liệu thời gian thực, hay sản phẩm thay thế website hiện hành. Khoảng cách, tồn kho và khung giờ khám đều là dữ liệu tại thời điểm snapshot,
  **trước khi đi tiêm nhất định phải gọi điện cho cơ sở y tế để xác nhận**.

## Cấu trúc thư mục

```

  index.html
  css/app.css
  js/
    app.js              Main flow / state management / view assembly
    ui.js               DOM builders (pure functions, no business logic)
    map.js              Leaflet map wrapper
    logic.js            Pure functions (time, filtering, sorting, URL state) - no DOM dependency, unit-testable
    i18n.js             Multilingual support: locale detection, string lookup, locale switching (see docs/I18N.md)
    data-source.js       Data source adapter (currently reads local JSON; switching to a live API only changes this file)
  data/hospitals.json   Normalized facility data (the only data file the front end reads)
  i18n/<lang>.json      UI strings (zh-Hant source text, en, ja, ko, id, vi, th, tl)
  vendor/leaflet, vendor/markercluster   Third-party map libraries (bundled static files, deployed together with public/)

data/raw/               Raw harvest files (.json.gz), used only to generate public/data/hospitals.json, not deployed with the site
data/districts-en.json  Official English names of the 22 counties/cities and 369 districts (used by romanize.mjs, not generated by pinyin)
scripts/
  dev-server.mjs        Zero-dependency static server for local development
  harvest.mjs           Harvests nationwide facility data from the current site → data/raw/*.json.gz (interim approach, see docs/HARVEST.md)
  normalize.mjs         Conversion script: data/raw/*.json.gz → public/data/hospitals.json
  romanize.mjs          English (Latin-alphabet) transliteration of facility names / addresses / districts, called by normalize.mjs
  keep-live-data.mjs    At deploy time, uses the newer data from the data branch (or the live site), sanitizing it first (used by GitHub Actions)
  publish-data.sh       Runs on a machine in Taiwan: harvest → check → push to the data branch → trigger deployment
  install-updater.sh    Installs a daily schedule on a Linux machine in Taiwan (systemd user timer)
.github/workflows/
  deploy.yml            Deploys to GitHub Pages (site from main, data from the data branch)
  freshness.yml         Checks daily whether the data has gone more than 36 hours without an update, and sends an email if it is too old
docs/
  DATA_SCHEMA.md        Format contract for public/data/hospitals.json
  HARVEST.md            How the 2026-09-21 snapshot was harvested, and known limitations
  I18N.md               Localization rules, medical terminology glossary, full key list (for translators)
  BASEMAP.md            Evaluation of basemap place-name languages, measured evidence and decisions
tests/
  logic.test.mjs        Unit tests for logic.js (node:test)
  i18n.test.mjs         Locale file consistency (keys, parameters, placeholder files)
  data.test.mjs         Data quality tests for hospitals.json, cross-validated against data/raw
  e2e.spec.mjs          Playwright end-to-end smoke tests (desktop + mobile)
  a11y.spec.mjs         Accessibility checks (report only, no fixes)
  harvest.test.mjs      Verifies harvest.mjs against a mock source server (mock-source.mjs)
  romanize.test.mjs     Hand-checked examples of English transliteration (names, addresses, edge cases)
```

## Chạy cục bộ

Máy chủ phát triển mặc định chỉ bind vào máy cục bộ (127.0.0.1); nếu muốn điện thoại trong cùng mạng kết nối vào để kiểm thử, hãy khởi động bằng `HOST=0.0.0.0 npm run dev`.

Yêu cầu: Node.js 18 trở lên (`"type": "module"`, sử dụng ES modules và `node:test`). Dự án này **không có quy trình build** —
thư mục `public/` chính là sản phẩm có thể triển khai trực tiếp; `leaflet`／`leaflet.markercluster` chỉ được liệt kê trong `devDependencies`,
dành cho trường hợp sau này cần tạo lại các tệp đã đóng gói dưới `public/vendor/`, khi vận hành chính thức không cần `npm install`.
Ngoại lệ duy nhất là **tạo dữ liệu**: `scripts/normalize.mjs` dùng `pinyin-pro` (devDependency, từ điển cục bộ, không cần kết nối mạng) để tạo phiên âm tiếng Anh,
trước khi chạy `npm run normalize`／`update-data` cần `npm install` trước (`publish-data.sh` sẽ tự động chạy `npm ci` khi thiếu gói).

```bash
npm run dev        # Start http://localhost:5173/ (override with the PORT environment variable)
```

## Chạy kiểm thử

```bash
npm test           # Unit tests + data quality tests (node --test)
npm run test:e2e   # Playwright end-to-end smoke tests (desktop 1440x900, mobile 390x844)
npm run test:a11y  # Accessibility checks (reports issues only, never modifies any file)
```

`test:e2e` và `test:a11y` yêu cầu môi trường đã cài `playwright` ở phạm vi toàn cục (dự án này giả định phiên bản 1.56) và trình duyệt đã được cài sẵn
(`PLAYWRIGHT_BROWSERS_PATH` trỏ tới thư mục đã cài Chromium); hai script này tự khởi động
`scripts/dev-server.mjs` trên một cổng ngẫu nhiên còn trống và tự động tắt khi kiểm thử kết thúc, **không cần khởi động máy chủ thủ công riêng**.

## Triển khai

`public/` là thư mục duy nhất cần đưa lên môi trường vận hành; chỉ cần sao chép sang bất kỳ máy chủ tĩnh nào (Nginx, IIS, S3+CDN, GitHub Pages, v.v.),
không cần bất kỳ chương trình phía máy chủ hay cơ sở dữ liệu nào.

### Lưu ý khi triển khai trên IIS

- **Kiểu MIME**: xác nhận `.json` được ánh xạ tới `application/json` (IIS thường đã tích hợp sẵn theo mặc định; nếu chưa có thì thêm vào
  `web.config` đoạn `<staticContent><mimeMap fileExtension=".json" mimeType="application/json" /></staticContent>`).
- **Nén tĩnh**: bật Static Compression của IIS (`httpCompression`／`urlCompression`),
  `hospitals.json` khi chưa nén khoảng 1,9 MB, sau khi bật gzip có thể giảm xuống còn khoảng 330 KB, ảnh hưởng rất lớn đến trải nghiệm của người dùng mạng di động.
- **HTTP header khuyến nghị**:

  | Header | Giá trị khuyến nghị | Lý do |
  |---|---|---|
  | `Content-Security-Policy` | Đồng bộ lên tầng máy chủ theo cấu hình `<meta http-equiv>` sẵn có trong `public/index.html` (`frame-ancestors 'none'` phải được đặt ở tầng HTTP header, thẻ `<meta>` không thể khai báo `frame-ancestors`) | Ngăn bị nhúng vào iframe (clickjacking), giới hạn nguồn script／style |
  | `X-Content-Type-Options` | `nosniff` | Tránh rủi ro do trình duyệt tự đoán kiểu MIME |
  | `Referrer-Policy` | `strict-origin-when-cross-origin` | Đã đặt trong `<meta name="referrer">`, tầng máy chủ có thể thêm một lớp nữa |
  | `X-Frame-Options` | `DENY` (nếu không dùng CSP `frame-ancestors`) | Như trên, là biện pháp dự phòng cho các trình duyệt cũ hơn |
- **Chiến lược bộ nhớ đệm**:

  | Đường dẫn | Cache khuyến nghị | Lý do |
  |---|---|---|
  | `data/hospitals.json` | Cache ngắn (ví dụ `Cache-Control: no-cache` hoặc `max-age=60~300`) | Dữ liệu được cập nhật định kỳ, cache quá dài sẽ khiến người dùng thấy tồn kho đã cũ |
  | `vendor/**`, `css/**`, `js/**` | Cache dài + đánh phiên bản (ví dụ `max-age=31536000, immutable`, kèm số phiên bản trong tên tệp hoặc query string) | Chỉ cần vô hiệu hóa khi nội dung thay đổi, giúp giảm đáng kể việc tải lại |
  | `index.html` | Cache ngắn hoặc không cache | Đảm bảo người dùng nhận được tham chiếu tài nguyên mới nhất |

  Hiện tại `scripts/dev-server.mjs` (chỉ dùng để phát triển cục bộ) trả về `Cache-Control: no-cache` cho mọi tệp; môi trường vận hành chính thức
  hãy cấu hình riêng ở tầng IIS／CDN theo bảng trên, không cần sửa nội dung bên trong `public/`.

## Dữ liệu được cập nhật như thế nào (cách làm hiện tại)

`npm run update-data` thực hiện lần lượt ba việc: `scripts/harvest.mjs` lấy dữ liệu cơ sở y tế toàn quốc từ website hiện hành, lưu thành
`data/raw/vaxmap_raw_YYYYMMDD-HHmm.json.gz`; `scripts/normalize.mjs` chuyển tệp thô mới nhất thành
`public/data/hospitals.json` (hợp đồng định dạng xem `docs/DATA_SCHEMA.md`); cuối cùng chạy kiểm tra dữ liệu. Bất kỳ bước nào thất bại đều dừng lại,
không để lại dữ liệu dở dang được đưa lên vận hành. Chi tiết và hạn chế của việc lấy dữ liệu xem `docs/HARVEST.md`.

Một lần lấy dữ liệu đầy đủ gửi khoảng 280 request tới website hiện hành, truyền gần 100 MB, mất 10–15 phút. Bản thân dữ liệu nguồn do các cơ sở y tế báo cáo hằng ngày,
**cập nhật 1–2 lần mỗi ngày là đủ, vui lòng không tăng tần suất hoặc giảm khoảng cách giữa các request**. Website hiện hành không chấp nhận kết nối từ nước ngoài, việc lấy dữ liệu phải chạy trên máy đặt trong nước; cách cập nhật tự động kết hợp với GitHub Pages xem ở mục kế tiếp.

Đây vẫn chỉ là **giải pháp chuyển tiếp**; giải pháp chính thức là để phía máy chủ xuất dữ liệu trực tiếp (xem "Phương án kết nối dữ liệu chính thức được đề xuất").

## Đa ngôn ngữ

Giao diện hỗ trợ tiếng Trung phồn thể (mặc định), English, 日本語, 한국어, Bahasa Indonesia, Tiếng Việt, ไทย, Filipino,
chuyển đổi bằng menu biểu tượng quả địa cầu ở đầu trang (không tải lại trang). Ngôn ngữ được lấy theo thứ tự từ URL `#lang=en`, lựa chọn lần trước (localStorage),
ngôn ngữ trình duyệt, nếu không có thì là tiếng Trung phồn thể; ngôn ngữ không phải mặc định sẽ được ghi vào URL có thể chia sẻ. Tên tỉnh/thành phố được dịch, và có thể tìm kiếm bằng tên tỉnh/thành phố tiếng nước ngoài (ví dụ “Taipei”).

**Phiên âm tiếng Anh của tên và địa chỉ cơ sở y tế**: mỗi cơ sở trong `hospitals.json` có thêm `nameEn`, `addrEn`, `cityEn`, `distEn`
(do `scripts/romanize.mjs` sinh ra theo quy tắc: thuật ngữ y khoa tra bảng thuật ngữ để dịch sang tiếng Anh, danh từ riêng dùng Hán ngữ bính âm, tỉnh/thành phố và quận/huyện dùng tên tiếng Anh chính thức,
địa chỉ theo thứ tự tiếng Anh của bưu điện, ví dụ「林文正耳鼻喉科診所」→ “Linwenzheng ENT Clinic”、「臺北市北投區明德路92號1樓」→
“1F, No. 92, Mingde Rd., Beitou District, Taipei City”). `meta.script` trong tệp ngôn ngữ quyết định cách hiển thị: `latin` (en, ko, id, vi, th, tl)
lấy tiếng Anh làm chính, nguyên văn tiếng Trung đặt ở dòng thứ hai (tiện đưa cho tài xế taxi hoặc quầy lễ tân xem); `han` (tiếng Trung phồn thể, tiếng Nhật) lấy tiếng Trung làm chính, tiếng Nhật có kèm thêm tên tiếng Anh.
Ở mọi ngôn ngữ, tìm kiếm đều đối chiếu đồng thời cả trường tiếng Trung và tiếng Anh (“Beitou”, “Mingde”, “ENT”, “Lin Wen Zheng” đều tìm được). Phiên âm được sinh bằng quy tắc máy,
không phải tên dịch chính thức, một số ít tên hoặc địa chỉ có thể không hoàn toàn chính xác.

- **Vị trí chuỗi**: `public/i18n/<lang>.json`, dạng key → chuỗi phẳng, `zh-Hant.json` là bản gốc.
- **Quy tắc key**: chia không gian tên theo chức năng (`filters.today`, `detail.call`, `status.ok.text`); các tham số như `{n}` phải được giữ nguyên;
  khi số lượng đúng bằng 1 thì dùng `<key>.one`; không được chứa HTML. Mỗi tệp ngôn ngữ phải có tập key giống hệt bản tiếng Trung phồn thể (`npm test` sẽ kiểm tra).
- **Thêm ngôn ngữ mới**: thêm mã vào `SUPPORTED_LANGS` của `logic.js` → sao chép `en.json`, sửa `meta.*`, đặt `"_status": "placeholder"`
  → thêm tùy chọn vào `#lang-select` của `index.html` → `npm test`. Các bước chi tiết và bảng đối chiếu thuật ngữ y khoa xem `docs/I18N.md`.
- **Trạng thái rà soát** (`_status` trong tệp): `zh-Hant` là bản gốc, `en` đã hoàn tất; `ja`, `ko`, `id`, `vi`, `th`, `tl` là
  `placeholder` (tạm hiển thị bằng tiếng Anh, chờ dịch).

## Triển khai lên GitHub Pages (kèm cập nhật dữ liệu tự động hằng ngày)

**Tiền đề quan trọng: website hiện hành của Taiwan CDC không chấp nhận kết nối từ nước ngoài.** Kiểm tra thực tế ngày 2026-09-21 cho thấy máy chạy GitHub Actions (đặt ở nước ngoài) khi kết nối tới
`vaxmap.cdc.gov.tw` bị hết thời gian chờ (`UND_ERR_CONNECT_TIMEOUT`). Do đó việc lấy dữ liệu không thể chạy trên GitHub,
mà chuyển thành "máy trong nước lấy dữ liệu, GitHub chỉ đảm nhiệm triển khai":

```
Linux machine in Taiwan (daily at 05:30, 12:30)  GitHub
  scripts/publish-data.sh                          
    ├─ harvest.mjs harvest → normalize.mjs → data checks  
    ├─ force-push hospitals.json to the data branch  ──►  data branch (always a single commit, so the repo does not grow)
    └─ gh workflow run deploy.yml             ──►  deploy.yml: take the site from main + the newer data from the data branch
                                                    → run sanitizing and checks again → deploy to Pages
```

`.github/workflows/deploy.yml` chạy khi push lên `main`, hoặc khi được kích hoạt thủ công／bởi `publish-data.sh`: lấy `hospitals.json` từ nhánh `data`,
làm sạch qua `scripts/keep-live-data.mjs --file` và xác nhận mới hơn snapshot trong `main` thì mới dùng; khi không có nhánh `data`
thì dùng lại snapshot trong `main`. `.github/workflows/freshness.yml` vào 09:00 giờ Taipei (UTC+8) mỗi ngày kiểm tra dữ liệu của nhánh `data`,
quá 36 giờ chưa cập nhật thì làm lượt chạy đó thất bại, GitHub sẽ gửi email thông báo cho chủ sở hữu repo (nghĩa là máy lấy dữ liệu không chạy hoặc liên tục thất bại);
mục "Ảnh chụp dữ liệu" trên giao diện website cũng sẽ hiển thị "đã N ngày chưa cập nhật".

Thiết lập lần đầu:

1. Tạo repo công khai trên GitHub và đẩy dự án này lên (nhánh mặc định phải là `main`).
2. Vào Settings → Pages của repo, đặt Source thành **GitHub Actions**, rồi chạy lại quy trình "triển khai" một lần.
3. Trên một máy Linux **đặt trong nước và kết nối được tới website hiện hành** (cần git, Node.js 20 trở lên, GitHub CLI đã chạy `gh auth login`),
   vào thư mục dự án và chạy thử thủ công một lần: `npm run publish-data`. Nếu thành công, sau 10–15 phút thời gian snapshot trên website sẽ được cập nhật.
4. Chạy `scripts/install-updater.sh` để cài lịch chạy hằng ngày. Script sẽ tạo riêng một thư mục chuyên dụng
   (`~/.local/share/vaxmap-updater`, tách biệt với thư mục bạn sửa mã, tự động đồng bộ `main` trước mỗi lần chạy),
   và thiết lập systemd user timer; các lịch bị lỡ do tắt máy sẽ được chạy bù sau khi khởi động. Gỡ cài đặt dùng `scripts/install-updater.sh --uninstall`.

Không khuyến nghị chuyển sang dùng máy chạy tự lưu trữ (self-hosted runner) của GitHub: trên repo **công khai**, pull request do bất kỳ ai gửi
đều có thể khiến mã được thực thi trên máy đó, GitHub cũng không khuyến khích cách dùng này. Cách làm ở trên chỉ cần máy đó "đẩy dữ liệu ra ngoài", không chấp nhận bất kỳ lệnh nào từ bên ngoài.

Khi dùng GitHub Pages cần lưu ý: gói miễn phí của Pages yêu cầu repo công khai; Pages không thể tùy chỉnh HTTP header,
vì vậy trong các header được đề xuất ở mục IIS phía trên, chỉ phần mà `<meta>` trong `index.html` có thể biểu đạt mới có hiệu lực (`frame-ancestors` thì không);
Pages cache cố định khoảng 10 phút cho mọi tệp, sau khi dữ liệu được cập nhật, người dùng có thể phải chờ tối đa 10 phút mới thấy.

## Phương án kết nối dữ liệu chính thức được đề xuất

API `POST /Home/GetHospitalData` của website hiện hành có các hạn chế sau, khiến front-end không thích hợp để gọi trực tiếp:

- Mỗi lần gọi chỉ trả về **20 bản ghi** cơ sở y tế, để lấy toàn bộ khoảng 4.660 bản ghi cần khoảng **280 lần** gọi phân trang;
- Mỗi phản hồi khoảng 390 KB, và **chứa HTML đã được render phía máy chủ** (không phải định dạng dữ liệu sạch), quy đổi ra thì lấy đủ toàn bộ
  dữ liệu phải truyền gần **97 MB**;
- Cần kèm header `X-Requested-With: XMLHttpRequest` thì mới được chấp nhận;
- **Không mở CORS**, phía trình duyệt không thể gọi trực tiếp xuyên tên miền.

**Cách làm đề xuất**: ở phía back-end (máy chủ nơi đặt website hiện hành hoặc môi trường có quyền truy cập cơ sở dữ liệu nguồn) tạo một **tác vụ định kỳ**,
cứ mỗi N phút (ví dụ 5–15 phút, tùy tần suất cập nhật dữ liệu) xuất trực tiếp từ cơ sở dữ liệu và sinh ra `hospitals.json` theo đúng định dạng của
`docs/DATA_SCHEMA.md` (sau khi chuẩn hóa khoảng 1,9 MB, nén gzip còn khoảng 330 KB; phiên âm tiếng Anh có thể tiếp tục dùng `scripts/romanize.mjs`),
rồi phát hành lên máy chủ tệp tĩnh hoặc CDN.

Một phương án khả thi khác là để nhóm phụ trách website hiện hành bổ sung một **endpoint JSON trả về toàn bộ dữ liệu** (phân trang hay không phân trang đều được, nhưng cần mở
CORS hoặc triển khai cùng tên miền), hiệu quả tương đương với việc xuất định kỳ ở trên.

Dù chọn cách nào, front-end chỉ cần thay đúng một tệp là `public/js/data-source.js` (đổi `fetch('./data/hospitals.json')`
thành gọi endpoint mới, và bảo đảm đối tượng trả về vẫn khớp cấu trúc `{ meta, vaccines, groups, hospitals }`),
phần mã còn lại hoàn toàn không cần thay đổi.

## An toàn thông tin

**Thư viện bên thứ ba** (kiểm tra ngày 2026-09-21): Leaflet 1.9.4 và leaflet.markercluster 1.5.3 đều là phiên bản ổn định mới nhất trên npm
(Leaflet 2.0 vẫn ở giai đoạn alpha, chuyển sang ESM thuần và bỏ biến toàn cục `L`, markercluster chưa tương thích, tạm thời không khuyến nghị nâng cấp).
Các tệp trong `public/vendor/` giống hệt từng bit với gói npm, `npm run verify-vendor` xác minh bằng sha256, `npm test` cũng bao gồm kiểm tra này.
`npm audit` cho kết quả 0 mục. Leaflet có một CVE chưa có bản vá là CVE-2025-69993 (`bindPopup()` sẽ render chuỗi truyền vào như HTML,
người bảo trì xác định đây là hành vi sẵn có đã được ghi trong tài liệu); website này **không dùng** popup／tooltip, mọi chuỗi dữ liệu đều được ghi bằng `textContent` hoặc thuộc tính, nên không bị ảnh hưởng.

**Bảo vệ phía front-end**: CSP của `index.html` không cho phép script và style nội tuyến, chỉ mở ảnh từ hai tên miền bản đồ nền; ngoài ra bật Trusted Types
(`public/js/trusted-types.js`), chỉ cho phép các chuỗi HTML cố định của Leaflet và `map.js` — sau này nếu sửa HTML của ghim đánh dấu hoặc chuỗi
bản quyền của bản đồ nền, phải cập nhật đồng bộ danh sách cho phép trong tệp đó, nếu không kiểm thử e2e sẽ thất bại do lỗi console. Liên kết ngoài luôn dùng `rel="noopener noreferrer"`,
URL đặt lịch hẹn chỉ chấp nhận https. Vị trí định vị của người dùng chỉ nằm trong bộ nhớ, không được ghi vào URL, bộ lưu trữ hay bất kỳ request nào (tuy nhiên khi phóng to bản đồ, máy chủ bản đồ nền có thể suy ra khu vực đại khái từ các request tile).

**Pipeline dữ liệu**: phản hồi từ website nguồn luôn được coi là không đáng tin. `scripts/sanitize.mjs` dùng danh sách trắng để dựng lại từng trường sẽ được phát hành
(loại bỏ ký tự điều khiển và ký tự điều khiển văn bản hai chiều, giới hạn độ dài, kiểm tra khoảng giá trị số và phạm vi tọa độ, kiểm tra định dạng số điện thoại và URL),
`normalize.mjs` và `keep-live-data.mjs` đều dùng nó làm chốt chặn cuối cùng; `harvest.mjs` đặt giới hạn cho từng phản hồi, tổng lượng truyền, số bản ghi mỗi trang và tổng số bản ghi.
Các kiểm thử liên quan nằm trong `tests/security.test.mjs`.

**GitHub Actions**: mỗi job dùng quyền tối thiểu (chỉ deploy có `pages: write`, không job nào có thể ghi vào repo),
mọi action đều được ghim vào commit SHA đầy đủ, `${{ }}` luôn được truyền qua `env:` chứ không viết trực tiếp vào câu lệnh, checkout không lưu lại thông tin xác thực.
Khi nâng cấp phiên bản action, vui lòng xác minh lại và cập nhật SHA. Nên vào Settings → Environments → github-pages của repo, xác nhận chỉ cho phép nhánh `main` triển khai.

**Hạn chế của GitHub Pages**: không thể đặt HTTP header, nên không có `frame-ancestors`／`X-Frame-Options` (ngăn bị website khác nhúng vào).
Website này không có trạng thái đăng nhập hay thao tác nhạy cảm có thể bị dụ nhấp chuột, rủi ro thấp; nếu chuyển sang triển khai trên máy chủ có thể đặt header, hãy bổ sung.

## Bản đồ nền

Bản đồ nền được chọn theo ngôn ngữ giao diện để địa danh đọc hiểu được (quá trình đánh giá và bằng chứng kiểm nghiệm thực tế xem `docs/BASEMAP.md`):

- **Tiếng Trung phồn thể**: "Bản đồ điện tử phiên bản phổ thông" (通用版電子地圖) `EMAP` của Trung tâm Đo đạc và Bản đồ Quốc gia (NLSC) (địa danh tiếng Trung, người dùng ở Đài Loan tải nhanh hơn), khi thất bại thì chuyển sang tile chính thức của OpenStreetMap.
- **Tiếng Nhật**: giống tiếng Trung phồn thể (người dùng tiếng Nhật đọc hiểu được tên đường bằng chữ Hán, và khớp với biển chỉ đường).
- **Các ngôn ngữ khác** (en, ko, id, vi, th, tl): NLSC "臺灣通用電子地圖EN" `EMAP8` (địa danh tiếng Anh toàn Đài Loan), khi thất bại thì chuyển sang OpenStreetMap, và hiển thị thông báo "địa danh có thể hiển thị bằng tiếng Trung". Hiện chưa có nguồn nào không cần khóa API cung cấp tên đường bằng tiếng Hàn, nên ko cũng dùng tiếng Anh.

**Người dùng có thể tự chuyển đổi**: trong chú giải (desktop ở góc dưới bên trái, mặc định mở rộng; điện thoại ở góc trên bên phải, mặc định thu gọn) có nút radio "Bản đồ nền" — giao diện tiếng Trung／tiếng Nhật có thể chọn
"Bản đồ điện tử phiên bản phổ thông" và "OpenStreetMap"; giao diện ngoại ngữ có thể chọn “NLSC (English)”, bản tiếng Trung của NLSC (địa danh khớp với biển chỉ đường) và “OpenStreetMap”.
Chọn xong bản đồ được đổi ngay, dòng bản quyền đổi theo; lựa chọn được ghi trong localStorage của trình duyệt với key `vaxmap.basemap`, **địa danh tiếng Trung và địa danh ngoại ngữ được ghi nhớ riêng thành hai loại**,
mỗi loại được áp dụng khi chuyển ngôn ngữ. Khi bản đồ nền được chọn tải thất bại, hệ thống vẫn tự động chuyển sang bản kế tiếp và hiển thị thông báo, nút radio cũng sẽ đổi sang bản đồ thực sự đang hiển thị.

Khi chuyển ngôn ngữ, bản đồ nền được đổi ngay lập tức, không tải lại trang. Thứ tự do `BASEMAP_CHAINS` trong `public/js/map.js` quyết định (phần tử đầu của mỗi chuỗi là mặc định,
các phần tử sau là dự phòng theo thứ tự; các lớp cùng một host được coi là hỏng cùng nhau); `img-src` trong CSP của `index.html` chỉ mở hai tên miền này (EMAP8 và EMAP cùng host). Khi kiểm thử, có thể thêm vào URL
`?tiles=nlsc`／`?tiles=osm`／`?tiles=nlscEn` để chỉ định bản đồ nền khởi đầu (phải nằm trong chuỗi của ngôn ngữ hiện tại), thêm `?tiles=fail` để mô phỏng bản đồ nền mặc định bị hỏng,
hoặc thêm dạng như `?tiles=fail:osm` để chỉ làm hỏng bản đồ nền được chỉ định.
**Trước khi chính thức đưa lên vận hành** nhất định phải:

- Xác nhận [chính sách sử dụng tile OSM](https://operations.osmfoundation.org/policies/tiles/). Máy chủ tile chính thức của OSM
  được vận hành bằng tiền quyên góp, không bảo đảm tính khả dụng, chính sách nêu rõ các mục đích lưu lượng lớn không được phụ thuộc vào nó, vi phạm có thể bị chặn không báo trước.
  Bản mẫu và trình diễn lưu lượng thấp thì không có vấn đề; nếu dùng làm bản đồ nền mặc định cho dịch vụ chính thức hướng ra công chúng, nên chuyển sang tile tự dựng hoặc nhà cung cấp tile thương mại
  (MapTiler, Stadia, Mapbox, v.v., phần lớn vẫn vẽ bản đồ từ dữ liệu OSM). Hiện mặc định của mọi ngôn ngữ đều là NLSC, OSM chỉ được dùng khi dự phòng hoặc người dùng tự chọn;
- Mô tả chính thức của NLSC về WMTS là "người dùng không cần đăng ký" vẫn có thể kết nối, nhưng không có giới hạn lưu lượng hay mức dịch vụ được công bố; bản đồ nền mặc định của mọi ngôn ngữ đều ở NLSC (EMAP／EMAP8),
  trước khi chính thức vận hành và lưu lượng tăng lên, nên nhân danh Taiwan CDC xác nhận với Trung tâm Đo đạc và Bản đồ Quốc gia (xem `docs/BASEMAP.md`).

## Hạn chế đã biết

- Dữ liệu là snapshot (cập nhật hai lần mỗi ngày), không phải thời gian thực; trước khi tiêm nhất định phải gọi điện cho cơ sở y tế để xác nhận.
- Khung giờ khám được biểu diễn bằng bitmask quy đổi từ dữ liệu của Cục Bảo hiểm Y tế Quốc gia (NHIA) cho buổi sáng／chiều／tối, chỉ là khung giờ xấp xỉ, không phải lịch khám chính xác.
- Tên và địa chỉ cơ sở y tế giữ nguyên văn từ nguồn (ví dụ「台北長庚紀念醫院」là tên chính thức), chỉ các trường tỉnh/thành phố và quận/huyện được thống nhất dùng chữ「臺」.
- Tên cơ sở y tế bằng tiếng Anh là phiên âm do máy sinh (tên người được viết liền theo bính âm, chỉ khoảng 25 bệnh viện nổi tiếng dùng tên tiếng Anh chính thức), không phải tên dịch chính thức;
  địa chỉ tiếng Anh được sinh theo định dạng của bưu điện, chỉ giữ số nhà đầu tiên.
- Văn bản giao diện của sáu ngoại ngữ (ja, ko, id, vi, th, tl) là bản nháp đầu do AI viết, trước khi chính thức công bố ra bên ngoài nên nhờ người bản ngữ rà soát.
- Các trạng thái như định vị, phạm vi bản đồ không được ghi vào URL có thể chia sẻ (URL hash), chỉ có điều kiện lọc và cơ sở y tế được chọn là được chia sẻ.
- Chưa kiểm thử thực tế trên IE／Android WebView phiên bản cũ; tile bản đồ có thể tải thất bại trong môi trường mạng không ổn định (có dự phòng tự động và chuyển đổi bản đồ nền thủ công).
