# Mapa ng Bakuna at Gamot Laban sa Trangkaso (vaxmap-next)

**語言／Language：** [繁體中文](README.md) ・ [English](README.en.md) ・ [日本語](README.ja.md) ・ [한국어](README.ko.md) ・ [Bahasa Indonesia](README.id.md) ・ [Tiếng Việt](README.vi.md) ・ [ไทย](README.th.md) ・ Filipino

Ito ay isang **concept prototype (Proof of Concept)** ng "Mapa ng Bakuna at Antiviral na Gamot Laban sa Trangkaso" (vaxmap.cdc.gov.tw) ng Centers for Disease Control, Ministry of Health and Welfare (Taiwan CDC),
na ginawa para ipakita ang isang front-end experience na mas mabilis at mas madaling gamitin kaysa sa kasalukuyang website. **Hindi ito opisyal na website**, hindi ito naka-deploy sa anumang domain ng gobyerno, at ang datos
**ay hindi real-time**. Ito ay mga snapshot na kinukuha mula sa kasalukuyang site dalawang beses bawat araw (ang unang snapshot ay noong 2026-09-21; para sa mekanismo ng pag-update, tingnan ang "Paano ina-update ang datos" at "Pag-deploy sa GitHub Pages"). Kung ikaw ang magpapatuloy ng proyektong ito,
inirerekomendang basahin muna ang `docs/DATA_SCHEMA.md` (ang data contract ng front end) at `docs/HARVEST.md` (kung paano nakuha ang snapshot at ano ang mga limitasyon nito).

## Ano ito at ano ang hindi

- Ito ay: isang purong static na website prototype na gumagana sa pagbasa lang ng iisang JSON file, na nagpapakita ng bagong disenyo ng pag-filter, listahan, interaksyon sa mapa, at mga URL na maibabahagi.
- Hindi ito: isang production system, isang real-time na pinagmumulan ng datos, o kapalit ng kasalukuyang site. Ang distansya, stock, at oras ng konsultasyon ay pawang datos noong kinuha ang snapshot,
  kaya **tumawag muna sa pasilidad bago magpabakuna**.

## Pagpapatakbo nang lokal

Naka-bind lang sa lokal na makina (127.0.0.1) ang dev server bilang default; para makakonekta ang mga telepono sa parehong network para sa pagsubok, simulan ito gamit ang `HOST=0.0.0.0 npm run dev`.

Kinakailangan: Node.js 18 o mas bago (`"type": "module"`, gumagamit ng ES modules at `node:test`). Ang proyektong ito ay **walang build process**:
ang nasa `public/` ay ang mismong output na maaaring i-deploy nang direkta, at ang `leaflet`／`leaflet.markercluster` ay nakalista lang sa `devDependencies`,
para sa hinaharap na kailangang buuing muli ang mga bundled file sa `public/vendor/`; hindi kailangan ng `npm install` sa production.
Ang tanging eksepsyon ay ang **pagbuo ng datos**: ang `scripts/normalize.mjs` ay gumagamit ng `pinyin-pro` (devDependency, lokal na diksyunaryo, hindi kumokonekta sa internet) para buuin ang English transliteration,
kaya kailangang mag-`npm install` muna bago patakbuhin ang `npm run normalize`／`update-data` (kusang nagpapatakbo ng `npm ci` ang `publish-data.sh` kapag may kulang na package).

```bash
npm run dev        # Start http://localhost:5173/ (override with the PORT environment variable)
```

## Pagpapatakbo ng mga test

```bash
npm test           # Unit tests + data quality tests (node --test)
npm run test:e2e   # Playwright end-to-end smoke tests (desktop 1440x900, mobile 390x844)
npm run test:a11y  # Accessibility checks (reports issues only, never modifies any file)
```

Ang `test:e2e` at `test:a11y` ay nangangailangan na naka-install nang global ang `playwright` sa environment (ang bersyong ipinapalagay ng proyektong ito ay 1.56) at na naka-install na ang mga browser
(ang `PLAYWRIGHT_BROWSERS_PATH` ay tumuturo sa direktoryong may naka-install nang Chromium). Ang dalawang script na ito ay kusang magsisimula ng
`scripts/dev-server.mjs` sa isang random na available na port at kusa itong isasara pagkatapos ng test, kaya **hindi na kailangang manu-manong simulan ang server**.

## Pag-deploy

Ang `public/` ang tanging direktoryong kailangang i-publish; kopyahin lang ito sa anumang static host (Nginx, IIS, S3+CDN, GitHub Pages, atbp.),
at hindi kailangan ng anumang server-side na programa o database.

### Mga dapat tandaan sa pag-deploy sa IIS

- **MIME type**: tiyaking naka-map ang `.json` sa `application/json` (karaniwang built-in na ito sa default ng IIS; kung wala,
  idagdag sa `web.config` ang `<staticContent><mimeMap fileExtension=".json" mimeType="application/json" /></staticContent>`).
- **Static compression**: i-enable ang Static Compression ng IIS (`httpCompression`／`urlCompression`).
  Ang `hospitals.json` ay humigit-kumulang 1.9 MB kapag hindi naka-compress, at bababa sa humigit-kumulang 330 KB kapag naka-enable ang gzip, na malaki ang epekto sa karanasan ng mga gumagamit ng mobile network.
- **Mga inirerekomendang HTTP header**:

  | Header | Inirerekomendang halaga | Dahilan |
  |---|---|---|
  | `Content-Security-Policy` | I-sync sa server level ang umiiral na setting ng `<meta http-equiv>` sa `public/index.html` (kailangang itakda ang `frame-ancestors 'none'` sa HTTP header level; hindi ito maidedeklara ng `<meta>` tag) | Pigilan ang pag-embed sa iframe (clickjacking) at limitahan ang pinagmumulan ng script/style |
  | `X-Content-Type-Options` | `nosniff` | Iwasan ang panganib na dulot ng paghula ng browser sa MIME type |
  | `Referrer-Policy` | `strict-origin-when-cross-origin` | Naitakda na sa `<meta name="referrer">`; maaaring magdagdag ng isa pang layer sa server level |
  | `X-Frame-Options` | `DENY` (kung hindi gagamitin ang CSP `frame-ancestors`) | Kapareho ng sa itaas; pananggalang para sa mas lumang mga browser |
- **Patakaran sa cache**:

  | Path | Inirerekomendang cache | Dahilan |
  |---|---|---|
  | `data/hospitals.json` | Maikling cache (halimbawa, `Cache-Control: no-cache` o `max-age=60~300`) | Regular na ina-update ang datos; ang masyadong mahabang cache ay magpapakita sa mga user ng lipas na stock |
  | `vendor/**`, `css/**`, `js/**` | Mahabang cache + versioning (halimbawa, `max-age=31536000, immutable`, kasama ang version number sa filename o query string) | Kailangan lang i-invalidate kapag nagbago ang nilalaman; malaki ang natitipid sa paulit-ulit na pag-download |
  | `index.html` | Maikling cache o walang cache | Tiyaking nakukuha ng user ang pinakabagong reference sa mga resource |

  Sa kasalukuyan, ang `scripts/dev-server.mjs` (para sa lokal na development lang) ay nagbabalik ng `Cache-Control: no-cache` para sa lahat ng file; sa production,
  i-configure ito sa antas ng IIS／CDN ayon sa talahanayan sa itaas; hindi kailangang baguhin ang nilalaman ng `public/` mismo.

## Paano ina-update ang datos (kasalukuyang paraan)

Ang `npm run update-data` ay nagsasagawa ng tatlong hakbang nang sunud-sunod: ang `scripts/harvest.mjs` ay kumukuha ng datos ng mga pasilidad sa buong bansa mula sa kasalukuyang site at sine-save ito bilang
`data/raw/vaxmap_raw_YYYYMMDD-HHmm.json.gz`; ang `scripts/normalize.mjs` ay kino-convert ang pinakabagong raw file tungo sa
`public/data/hospitals.json` (tingnan ang `docs/DATA_SCHEMA.md` para sa format contract); sa huli, tumatakbo ang data check. Kapag pumalya ang alinmang hakbang, humihinto ang proseso,
kaya walang kalahating datos na mai-publish. Para sa mga detalye at limitasyon ng pagkuha ng datos, tingnan ang `docs/HARVEST.md`.

Ang isang buong harvest ay nagpapadala ng humigit-kumulang 280 request sa kasalukuyang site, naglilipat ng halos 100 MB, at tumatagal ng 10–15 minuto. Ang source data mismo ay araw-araw na ini-ulat ng mga pasilidad,
kaya **sapat na ang 1–2 update kada araw; huwag dagdagan ang dalas o bawasan ang pagitan ng mga request**. Hindi tumatanggap ng koneksyon mula sa ibang bansa ang kasalukuyang site, kaya kailangang patakbuhin ang harvest sa isang makina sa loob ng Taiwan; para sa awtomatikong pag-update kasama ang GitHub Pages, tingnan ang susunod na seksyon.

Ito ay **pansamantalang paraan** pa rin; ang nararapat na paraan ay ang direktang pag-export ng datos mula sa server side (tingnan ang "Inirerekomendang opisyal na integrasyon ng datos").

Ang **seksyon ng impormasyon sa pagbabakuna** (`public/data/info/<lang>.json`) ay may hiwalay na pipeline: ang `npm run update-info` ay nagsasagawa nang sunud-sunod ng
`scripts/harvest-info.mjs` (kinukuha ang pahina ng "Vaccination" ng Taiwan CDC, ipinaparse ang bawat card sa mga talata, listahan, talahanayan, link, at attachment,
nililinis gamit ang allowlist, at isinusulat sa `data/info/source.json`), `scripts/translate-info.mjs` (ipinapadala lang sa Anthropic API ang mga bloke na nagbago ang nilalaman
para isalin sa 7 wika; naka-cache ang resulta sa `data/info/translations.json`, kaya hindi na muling ipinapadala ang mga hindi nagbago; kapag walang naka-set na `ANTHROPIC_API_KEY`, walang pagsasalin,
at ang mga file ng banyagang wika ay inilalabas gamit ang orihinal na Traditional Chinese at minamarkahang hindi pa naisasalin), at sa huli ay bine-verify ang 8 output file. Kapag hindi maabot ang pahina o nagbago ang layout nito, walang isusulat na file at ginagamit ng site ang nakaraang bersyon.
Isang pahina lang ang kinukuha sa bawat run, at ang gastos sa pagsasalin para sa karaniwang pagbabago sa iisang bloke ay humigit-kumulang US$0.06; para sa mga detalye, estimate ng gastos, at kung paano puwersahing isalin muli, tingnan ang `docs/INFO_PIPELINE.md`.

## Pahina ng impormasyon sa pagbabakuna (info.html)

Bukod sa mapa, may hiwalay na pahinang "Impormasyon sa Pagbabakuna" ang site (`public/info.html`, mapapalitan sa navigation ng header), na ang nilalaman ay isinasabay mula sa website ng Taiwan CDC
na "115年度左流右新護肺顧心 疫苗接種專區" at inayos muli bilang madaling basahing mga card: health coin (ilang coin ang bawat isa sa tatlong bakuna), mga karapat-dapat sa libreng pagbabakuna
(mga talahanayan ng una／ikalawang yugto, na nagiging mga card sa mobile), kung saan puwedeng magpabakuna (kasama ang button na "Buksan sa mapa" at mga link sa health bureau ng bawat lungsod/county), mga paalala at materyal pangkalusugan
(PDF／video), mga brand ng bakuna, mga madalas itanong, at mga link sa press release. Bawat bloke ay nagpapakita ng petsa ng huling update ng source at link pabalik sa kaukulang bahagi ng opisyal na website.
Available ito sa walong wika: ang Traditional Chinese ang orihinal, at ang iba ay machine translation (ang unang batch ay inangkat mula sa draft na nasuri ng tao; pagkatapos nito, araw-araw na awtomatikong isinasalin ang mga bloke na nagbago lang);
ang mga bloke na hindi pa naisasalin ay minamarkahan at ipinapakita sa orihinal na teksto. Binabasa lang ng front end ang `public/data/info/<lang>.json`, lahat ng teksto ay isinusulat bilang plain text, at ang mga link ay limitado sa
`*.gov.tw`／`*.gov.taipei`／YouTube (tingnan ang `docs/INFO_SCHEMA.md`). Para sa mekanismo ng pag-update, tingnan ang "Paano ina-update ang datos"; ang code ay nasa
`public/js/info*.js`, at ang mga test ay `tests/e2e-info.spec.mjs` at `tests/info-ui.test.mjs`.

## Multilingual (i18n)

Sinusuportahan ng interface ang Traditional Chinese (default), English, 日本語, 한국어, Bahasa Indonesia, Tiếng Việt, ไทย, at Filipino,
at mapapalitan ito sa pamamagitan ng globe icon menu sa header (hindi nire-reload ang pahina). Ang wika ay kinukuha, ayon sa pagkakasunod, mula sa URL na `#lang=en`, sa huling pinili (localStorage),
at sa wika ng browser; kung wala, Traditional Chinese ang gagamitin. Ang hindi-default na wika ay isinusulat sa maibabahaging URL. Isinasalin ang mga pangalan ng lungsod/county, at maaaring maghanap gamit ang pangalan nila sa banyagang wika (halimbawa, “Taipei”).

**English transliteration ng mga pangalan at address ng pasilidad**: bawat pasilidad sa `hospitals.json` ay may karagdagang `nameEn`, `addrEn`, `cityEn`, `distEn`
(binubuo ng `scripts/romanize.mjs` gamit ang mga panuntunan: ang mga terminong medikal ay isinasalin sa English gamit ang glossary, ang mga pangngalang pantangi ay gumagamit ng Hanyu Pinyin, ang mga lungsod/county at distrito ay gumagamit ng opisyal na English na pangalan,
at ang address ay sumusunod sa pagkakasunod-sunod ng English address ng koreo, halimbawa, 「林文正耳鼻喉科診所」→ “Linwenzheng ENT Clinic”, 「臺北市北投區明德路92號1樓」→
“1F, No. 92, Mingde Rd., Beitou District, Taipei City”). Ang `meta.script` sa locale file ang nagtatakda kung paano ipapakita: sa `latin` (en, ko, id, vi, th, tl),
English ang pangunahin at nasa ikalawang linya ang orihinal na Chinese (madaling ipakita sa taxi driver o sa counter); sa `han` (Traditional Chinese, Japanese), Chinese ang pangunahin, at may kalakip na English na pangalan ang Japanese.
Sa anumang wika, sabay na tinutugma ng paghahanap ang mga field sa Chinese at English (matatagpuan ang “Beitou”, “Mingde”, “ENT”, “Lin Wen Zheng”). Ang transliteration ay binubuo ng mga panuntunan ng makina,
hindi opisyal na salin, at maaaring hindi ganap na tama ang ilang pangalan o address.

- **Lokasyon ng mga string**: `public/i18n/<lang>.json`, flat na key → string; ang `zh-Hant.json` ang orihinal na teksto.
- **Mga panuntunan sa key**: hinahati sa namespace ayon sa feature (`filters.today`, `detail.call`, `status.ok.text`); dapat panatilihin ang mga parameter tulad ng `{n}`;
  kapag eksaktong 1 ang bilang, gamitin ang `<key>.one`; bawal maglaman ng HTML. Dapat may eksaktong parehong mga key sa Traditional Chinese ang bawat locale file (sinusuri ito ng `npm test`).
- **Pagdaragdag ng wika**: idagdag ang code sa `SUPPORTED_LANGS` ng `logic.js` → kopyahin ang `en.json`, baguhin ang `meta.*`, at itakda ang `"_status": "placeholder"`
  → magdagdag ng option sa `#lang-select` ng `index.html` → `npm test`. Para sa detalyadong hakbang at glossary ng mga terminong medikal, tingnan ang `docs/I18N.md`.
- **Estado ng review** (`_status` sa loob ng file): ang `zh-Hant` ang orihinal at tapos na ang `en`; ang `ja`, `ko`, `id`, `vi`, `th`, `tl` ay
  `placeholder` (pansamantalang ipinapakita sa English, naghihintay ng pagsasalin).

## Pag-deploy sa GitHub Pages (kasama ang araw-araw na awtomatikong pag-update ng datos)

**Mahalagang paunang kondisyon: hindi tumatanggap ng koneksyon mula sa ibang bansa ang kasalukuyang site ng Taiwan CDC.** Sa pagsubok noong 2026-09-21, ang mga execution machine ng GitHub Actions (na nasa ibang bansa) ay nag-time out ang koneksyon
papunta sa `vaxmap.cdc.gov.tw` (`UND_ERR_CONNECT_TIMEOUT`). Kaya hindi maaaring patakbuhin sa GitHub ang pagkuha ng datos;
ginawa itong "ang makina sa loob ng Taiwan ang kumukuha ng datos, at ang GitHub ay para lang sa deployment":

```
Linux machine in Taiwan (daily at 05:30, 12:30)  GitHub
  scripts/publish-data.sh                          
    ├─ fetch the previous data branch (translation cache)
    ├─ harvest.mjs harvest → normalize.mjs → data checks  
    ├─ harvest-info.mjs → translate-info.mjs → checks (vaccination info, translating only changed blocks)
    ├─ force-push hospitals.json, info/*.json      ──►  data branch (always a single commit, so the repo does not grow)
    └─ gh workflow run deploy.yml only if changed  ──►  deploy.yml: take the site from main + the newer data from the data branch
                                                    → run sanitizing and checks again → deploy to Pages
```

Tumatakbo ang `.github/workflows/deploy.yml` kapag may push sa `main`, o kapag ito ay na-trigger nang mano-mano／ng `publish-data.sh`: kinukuha nito ang `hospitals.json` mula sa `data` branch,
nilalinis ito at kinukumpirma gamit ang `scripts/keep-live-data.mjs --file` na mas bago ito kaysa sa snapshot sa `main` bago gamitin; kung walang `data`
branch, ginagamit ang snapshot sa `main`. Ang `.github/workflows/freshness.yml` ay sumusuri araw-araw ng 09:00 Taipei time (UTC+8) sa datos ng `data` branch;
kapag lumampas sa 36 oras na walang update, ibabagsak nito ang run na iyon at magpapadala ang GitHub ng email sa may-ari ng repo (ibig sabihin, hindi tumatakbo o palaging pumapalya ang harvesting machine);
ipapakita rin ng "Data snapshot" sa screen ng website ang "N araw nang hindi na-update".

Sa parehong daan dumadaan ang seksyon ng impormasyon sa pagbabakuna: pagkatapos ng datos ng mga pasilidad, pinapatakbo ng `publish-data.sh` ang `harvest-info.mjs` at `translate-info.mjs`, at itinutulak sa `data` branch ang
`info/<lang>.json` kasama ang orihinal na teksto na `info/source.json` at ang translation cache na `info/translations.json` (kaya nananatili ang cache sa pagitan ng mga run,
at hindi na muling binabayaran ang pagsasalin ng mga bloke na hindi nagbago); kapag pumalya ang alinman sa datos ng pasilidad o impormasyon sa pagbabakuna, normal pa ring nalalathala ang isa pa, at ang pumalyang bahagi ay gumagamit ng nakaraang bersyon.
Kapag walang pagbabagong makakaapekto sa screen ng site sa dalawa, hindi tina-trigger ang deployment. Kinukuha ng `deploy.yml` ang `info/<lang>.json` mula sa `data` branch at bine-verify ang bawat file gamit ang
`scripts/keep-live-data.mjs --info-dir` (mahigpit na pagsusuri ng `sanitize-info.mjs`), at kinukumpirmang mas bago ito kaysa sa nasa `main` bago gamitin; kapag walang ganitong mga file sa `data` branch,
ginagamit ang bersyon sa `main`. Sinusuri rin ng `freshness.yml` ang oras ng huling pagkuha sa `info/source.json`; kapag lumampas sa 36 oras, babala lang ang ilalabas (walang email);
oras ng pagkuha ang tinitingnan nito at hindi ang nilalaman ng source, kaya hindi ito magbibigay ng maling alarma kapag ilang araw na hindi nagbago ang pahina ng Taiwan CDC.

**Susi sa pagsasalin**: i-update ang `~/.config/vaxmap-updater/env` sa makina ng updater (gumagawa ng template ang `install-updater.sh` at itinatakda ito sa `chmod 600`; niloload ito ng systemd sa pamamagitan ng
`EnvironmentFile=`) at ilagay ang `ANTHROPIC_API_KEY=…` para i-enable ang pagsasalin; may bisa ito sa susunod na run, at binabasa rin ang file na ito kapag manu-manong pinatakbo ang `npm run publish-data`.
Nasa makinang ito lang ang susi; hindi ito napupunta sa git o sa GitHub. Kapag walang inilagay na susi, normal pa rin ang lahat, ngunit orihinal na Traditional Chinese ang ipapakita sa mga pahina ng banyagang wika.

Unang setup:

1. Gumawa ng pampublikong repo sa GitHub at i-push ang proyektong ito (dapat `main` ang default branch).
2. Pumunta sa Settings → Pages ng repo, itakda ang Source sa **GitHub Actions**, at patakbuhin muli ang "deploy" workflow.
3. Sa isang Linux machine na **nasa loob ng Taiwan at nakakakonekta sa kasalukuyang site** (kailangan ng git, Node.js 20 o mas bago, at GitHub CLI na napatakbo na ang `gh auth login`),
   pumasok sa folder ng proyekto at subukan muna nang mano-mano: `npm run publish-data`. Kapag matagumpay, mag-a-update ang oras ng snapshot sa website pagkalipas ng 10–15 minuto.
4. Patakbuhin ang `scripts/install-updater.sh` para i-install ang araw-araw na iskedyul. Gagawa ito ng hiwalay na dedikadong folder
   (`~/.local/share/vaxmap-updater`, hiwalay sa folder kung saan ninyo ineedit ang code, at awtomatikong sini-sync ang `main` bago ang bawat run),
   at magse-set up ng systemd user timer; ang mga iskedyul na nalampasan dahil naka-off ang makina ay patatakbuhin pagkatapos mag-boot. Para i-uninstall, gamitin ang `scripts/install-updater.sh --uninstall`.
5. (Opsyonal) Para isalin ang seksyon ng impormasyon sa pagbabakuna, i-edit ang `~/.config/vaxmap-updater/env` at ilagay ang `ANTHROPIC_API_KEY=` (susing ginawa sa Anthropic Console).

Hindi inirerekomendang gumamit ng self-hosted runner ng GitHub: sa isang **pampublikong** repo, ang pull request na isinumite ng sinuman
ay maaaring magpatakbo ng code sa makinang iyon, at hindi rin ito inirerekomenda ng GitHub. Ang paraan sa itaas ay nangangailangan lang na ang makinang iyon ay "mag-push palabas" at hindi tumatanggap ng anumang utos mula sa labas.

Mga dapat tandaan sa paggamit ng GitHub Pages: ang libreng plano ng Pages ay nangangailangan ng pampublikong repo; hindi maaaring i-customize ang mga HTTP header sa Pages,
kaya sa mga header na inirerekomenda sa seksyon ng IIS sa itaas, ang mga maipapahayag lang ng `<meta>` sa `index.html` ang mananatiling epektibo (hindi ang `frame-ancestors`);
ang Pages ay naka-cache nang humigit-kumulang 10 minuto para sa lahat ng file, kaya pagkatapos ng update ng datos, hanggang 10 minuto bago ito makita ng mga user.

## Inirerekomendang opisyal na integrasyon ng datos

Ang API ng kasalukuyang site na `POST /Home/GetHospitalData` ay may mga sumusunod na limitasyon kaya hindi ito angkop na tawagin nang direkta ng front end:

- Bawat tawag ay nagbabalik lang ng **20 record** ng pasilidad; para makuha ang lahat ng humigit-kumulang 4,660 record, kailangan ng humigit-kumulang **280 paged na tawag**;
- Bawat response ay humigit-kumulang 390 KB at **naglalaman ng HTML na na-render na sa server side** (hindi malinis na data format), kaya sa kabuuan, ang pagkuha ng buong
  datos ay naglilipat ng halos **97 MB**;
- Kailangang may kasamang header na `X-Requested-With: XMLHttpRequest` para tanggapin;
- **Walang bukas na CORS**, kaya hindi ito matatawag nang direkta ng browser mula sa ibang domain.

**Inirerekomendang paraan**: sa back end (ang server kung nasaan ang kasalukuyang site, o isang environment na may access sa source database), gumawa ng **scheduled job**
na, kada N minuto (halimbawa, 5–15 minuto, depende sa dalas ng pag-update ng datos), direktang nag-e-export mula sa database at naglalabas ng `hospitals.json`
na sumusunod sa format ng `docs/DATA_SCHEMA.md` (humigit-kumulang 1.9 MB pagkatapos ng normalization, humigit-kumulang 330 KB kapag naka-gzip; magagamit pa rin ang `scripts/romanize.mjs` para sa English transliteration),
at i-publish ito sa isang static file host o CDN.

Isa pang posibleng opsyon ay ang pagdaragdag ng pangkat ng kasalukuyang site ng **JSON endpoint na nagbabalik ng buong datos** (may pagination man o wala, ngunit kailangang bukas ang
CORS o naka-deploy sa parehong domain), na katumbas ng epekto ng scheduled export sa itaas.

Alinman ang piliin, iisang file lang ang kailangang palitan sa front end: ang `public/js/data-source.js` (palitan ang `fetch('./data/hospitals.json')`
ng tawag sa bagong endpoint, at tiyaking ang ibinabalik na object ay sumusunod pa rin sa istrukturang `{ meta, vaccines, groups, hospitals }`),
at hindi na kailangang galawin ang natitirang code.

## Seguridad

**Mga third-party library** (sinuri noong 2026-09-21): ang Leaflet 1.9.4 at leaflet.markercluster 1.5.3 ay parehong pinakabagong stable na bersyon sa npm
(ang Leaflet 2.0 ay alpha pa rin, naging pure ESM, at inalis ang global na `L`; hindi pa ito compatible sa markercluster, kaya hindi muna inirerekomendang mag-upgrade).
Ang mga file sa `public/vendor/` ay byte-for-byte na kapareho ng mga npm package; bine-verify ito ng `npm run verify-vendor` gamit ang sha256, at kasama rin ito sa `npm test`.
Ang `npm audit` ay 0 ang nakita. May isang CVE na walang patch pa, ang CVE-2025-69993 (ang `bindPopup()` ay nire-render bilang HTML ang ipinasang string,
na itinuturing ng maintainer na dokumentadong umiiral na behavior); **hindi gumagamit** ang site na ito ng popup／tooltip, at lahat ng data string ay isinusulat gamit ang `textContent` o attribute, kaya hindi ito apektado.

**Proteksyon sa front end**: hindi pinapayagan ng CSP ng `index.html` ang inline script at style, at dalawang basemap domain lang ang bukas para sa mga imahe; naka-enable rin ang Trusted Types
(`public/js/trusted-types.js`), na pumapayag lang sa mga nakapirming HTML string ng Leaflet at ng `map.js` — kung sa hinaharap ay babaguhin ang HTML ng pin o ang
copyright string ng basemap, kailangang i-update nang sabay ang allowlist ng file na iyon, kung hindi ay babagsak ang e2e test dahil sa error sa console. Ang lahat ng external link ay may `rel="noopener noreferrer"`,
at https lang ang tinatanggap ng URL ng reservation. Ang lokasyon ng user ay nasa memory lang, at hindi isinusulat sa URL, storage, o anumang request (ngunit kapag nag-zoom in sa mapa, maaaring mahinuha ng basemap server ang tinatayang lugar mula sa mga tile request).

**Data pipeline**: ang mga response ng source website ay laging ituturing na hindi mapagkakatiwalaan. Ang `scripts/sanitize.mjs` ay muling binubuo ang bawat field na ipa-publish gamit ang allowlist
(inaalis ang control character at bidirectional text control character, nililimitahan ang haba, sinusuri ang saklaw ng numero at coordinate, at sinusuri ang format ng telepono at URL);
ang `normalize.mjs` at `keep-live-data.mjs` ay parehong gumagamit nito bilang huling harang; ang `harvest.mjs` ay may limitasyon para sa bawat response, kabuuang inilipat na datos, bilang ng record kada pahina, at kabuuang bilang ng record.
Ang mga kaugnay na test ay nasa `tests/security.test.mjs`.
Ganito rin ang pagtrato sa seksyon ng impormasyon sa pagbabakuna: ang `harvest-info.mjs` ay gumagamit ng allowlist parser na walang idinaragdag na package at kumukuha lang ng mga talata, listahan, talahanayan, at link (buong itinatapon ang script, event attribute, iframe, atbp.);
ang mga link ay pinapanatili lang kung https at ang host ay nasa allowlist (`*.gov.tw`, `*.gov.taipei`, YouTube; tingnan ang `docs/INFO_SCHEMA.md`); ang output ng machine translation ay tinatanggap lang kung eksaktong kapareho ng istruktura ng orihinal, at ang mga URL ay laging kinukuha sa orihinal na teksto;
bine-verify ang lahat ng file gamit ang `scripts/sanitize-info.mjs` bago isulat at bago i-deploy (ang mga kaugnay na test ay nasa `tests/info.test.mjs`).

**GitHub Actions**: least privilege ang bawat job (ang deploy lang ang may `pages: write`, at walang job na makakasulat sa repo),
lahat ng action ay naka-pin sa buong commit SHA, ang `${{ }}` ay laging ipinapasa sa pamamagitan ng `env:` at hindi direktang isinusulat sa command, at hindi iniiwan ng checkout ang mga credential.
Kapag nag-a-upgrade ng bersyon ng action, muling beripikahin at i-update ang SHA. Inirerekomendang pumunta sa Settings → Environments → github-pages ng repo at tiyaking `main` branch lang ang pinapayagang mag-deploy.

**Mga limitasyon ng GitHub Pages**: hindi makapagtakda ng HTTP header, kaya walang `frame-ancestors`／`X-Frame-Options` (pananggalang laban sa pag-embed ng ibang website).
Walang login state o sensitibong operasyon na maaaring linlangin ang user na i-click ang site na ito, kaya mababa ang panganib; kung ililipat sa host na nagpapahintulot magtakda ng header, idagdag ang mga ito.

## Basemap

Pinipili ang basemap ayon sa wika ng interface, para maintindihan ang mga pangalan ng lugar (tingnan ang `docs/BASEMAP.md` para sa proseso ng pagsusuri at ebidensya ng pagsubok):

- **Traditional Chinese**: ang "Taiwan e-Map" (通用版電子地圖) `EMAP` ng National Land Surveying and Mapping Center (NLSC) (mga pangalan ng lugar sa Chinese; mas mabilis mag-load para sa mga user sa Taiwan); kapag pumalya, lilipat sa opisyal na tile ng OpenStreetMap.
- **Japanese**: kapareho ng Traditional Chinese (nauunawaan ng mga gumagamit ng Japanese ang mga kanji na pangalan ng kalsada, at tugma ito sa mga karatula sa kalsada).
- **Iba pang wika** (en, ko, id, vi, th, tl): ang "Taiwan e-Map EN" (臺灣通用電子地圖EN) `EMAP8` ng NLSC (mga pangalan ng lugar sa English para sa buong Taiwan); kapag pumalya, lilipat sa OpenStreetMap at magpapakita ng paalalang "maaaring ipakita sa Chinese ang mga pangalan ng lugar". Sa kasalukuyan, walang key-free na source na nagbibigay ng mga pangalan ng kalye sa Korean, kaya English din ang ginagamit para sa ko.

**Maaaring magpalit ang user nang mag-isa**: sa loob ng legend (kaliwang-ibaba sa desktop, naka-expand bilang default; kanang-itaas sa mobile, naka-collapse bilang default) ay may radio button na "Basemap" — sa Chinese／Japanese na interface,
mapipili ang "Taiwan e-Map" (通用版電子地圖) at "OpenStreetMap"; sa banyagang interface, mapipili ang “NLSC (English)”, ang Chinese na bersyon ng NLSC (tugma ang mga pangalan ng lugar sa mga karatula) at “OpenStreetMap”.
Agad na nagpapalit ng mapa ang pagpili, at sumusunod ang copyright bar; ang pinili ay naka-save sa localStorage ng browser sa `vaxmap.basemap`, **magkahiwalay na sine-save ang dalawang kategorya: pangalan ng lugar sa Chinese at pangalan ng lugar sa banyagang wika**,
at ina-apply ang bawat isa kapag nagpalit ng wika. Kapag pumalya ang pag-load ng napiling basemap, kusa pa ring lilipat sa susunod at magpapakita ng paalala, at ang radio button ay ililipat din sa basemap na aktwal na ipinapakita.

Agad na napapalitan ang basemap kapag nagpalit ng wika, nang hindi nire-reload ang pahina. Ang pagkakasunod-sunod ay tinutukoy ng `BASEMAP_CHAINS` sa `public/js/map.js` (ang una sa bawat chain ang default,
ang mga kasunod ay fallback ayon sa pagkakasunod; ang mga layer sa parehong host ay ituturing na sabay na pumalya); ang CSP `img-src` ng `index.html` ay nagbubukas lang ng dalawang domain na ito (magkapareho ng host ang EMAP8 at EMAP). Sa pagsubok, maaaring idagdag sa URL ang
`?tiles=nlsc`／`?tiles=osm`／`?tiles=nlscEn` para tukuyin ang panimulang basemap (dapat nasa chain ng kasalukuyang wika), `?tiles=fail` para gayahin ang pagpalya ng default na basemap,
o mga anyong tulad ng `?tiles=fail:osm` para pumalya lang ang tinukoy na basemap.
**Bago ang opisyal na paglulunsad**, tiyaking gawin ang mga sumusunod:

- Kumpirmahin ang [patakaran sa paggamit ng OSM tile](https://operations.osmfoundation.org/policies/tiles/). Ang opisyal na OSM tile server
  ay pinapatakbo sa pamamagitan ng donasyon at walang garantiya ng availability; malinaw sa patakaran na hindi ito dapat asahan para sa mataas na trapiko, at maaaring i-block nang walang babala kapag nilabag.
  Walang problema para sa mga prototype at mababang-trapikong demo; kung gagamitin bilang default na basemap ng opisyal na pampublikong serbisyo, inirerekomendang lumipat sa self-hosted na tile o commercial tile provider
  (MapTiler, Stadia, Mapbox, atbp.; karamihan ay gumagamit pa rin ng datos ng OSM sa paggawa ng mapa). Sa kasalukuyan, NLSC ang default ng bawat wika, at ginagamit lang ang OSM bilang fallback o kapag ito ang pinili ng user;
- Ayon sa opisyal na paliwanag ng NLSC sa WMTS, "hindi kailangang mag-apply ang user" para makakonekta, ngunit walang pampublikong limitasyon sa trapiko o service level; NLSC (EMAP／EMAP8) ang default na basemap ng bawat wika,
  kaya bago ang opisyal na paglulunsad at bago lumaki ang trapiko, inirerekomendang kumpirmahin sa National Land Surveying and Mapping Center (NLSC) sa ngalan ng Taiwan CDC (tingnan ang `docs/BASEMAP.md`).

## Suporta ng browser

Gumagamit ng mga modernong browser API (`fetch`, ES modules, CSS Grid, `<details>`, `prefers-color-scheme`),
at ang target ay ang Chrome, Edge, Firefox, at Safari (kasama ang iOS Safari) sa nakaraang dalawang taon. Hindi sinusuportahan ang IE11, at walang ginawang kaugnay na polyfill.

## Mga kilalang limitasyon

- Snapshot ang datos (ina-update dalawang beses kada araw), hindi real-time; tumawag muna sa pasilidad para kumpirmahin bago magpabakuna.
- Ang oras ng konsultasyon ay kino-convert mula sa datos ng National Health Insurance Administration tungo sa bitmask na kumakatawan sa umaga／hapon／gabi; tinatayang oras lang ito, hindi eksaktong iskedyul ng outpatient.
- Pinapanatili ang orihinal na teksto ng source sa mga pangalan at address ng pasilidad (halimbawa, ang 「台北長庚紀念醫院」 ay ang opisyal na pangalan); tanging ang mga field ng lungsod/county at distrito ang pinag-isa sa 「臺」.
- Ang mga English na pangalan ng pasilidad ay machine transliteration (ang mga pangalan ng tao ay pinagdurugtong na pinyin, at humigit-kumulang 25 kilalang ospital lang ang gumagamit ng opisyal na English na pangalan), hindi opisyal na salin;
  ang English address ay binubuo ayon sa format ng koreo, at ang unang numero ng bahay lang ang pinapanatili.
- Ang teksto ng interface sa anim na banyagang wika (ja, ko, id, vi, th, tl) ay AI draft; bago ilabas sa publiko, dapat ipa-review sa mga native speaker.
- Ang mga estado tulad ng lokasyon at saklaw ng mapa ay hindi isinusulat sa maibabahaging URL (URL hash); ang mga kondisyon ng filter at napiling pasilidad lang ang ibinabahagi.
- Hindi pa nasubok ang IE／lumang Android WebView; maaaring pumalya ang pag-load ng mga map tile sa hindi matatag na network (may awtomatikong fallback at manu-manong pagpapalit ng basemap).

## Mga pagkakaiba mula sa kasalukuyang site

| Problema ng kasalukuyang site | Paraan ng prototype na ito |
|---|---|
| Kailangang isara muna ang nakaharang na announcement window pagpasok sa site | Ginawang banner sa header ang announcement na maaaring isara at hindi humaharang sa operasyon |
| Humihingi ng datos nang synchronous XHR sa batches na "bawat 20 record" | Isang JSON lang ang nilo-load nang sabay-sabay (humigit-kumulang 330 KB gzip, kasama ang English transliteration); lokal na nagfi-filter／nagso-sort ang front end |
| Ang pin sa mapa ay nagpapakita lang ng "may konsultasyon／sarado" | Ang pin ay gumagamit ng hugis＋kulay para ipahayag nang sabay ang tatlong estado: "may konsultasyon ngayon" at "may stock ang napiling item o wala" |
| Walang listahan; pin lang sa mapa ang maki-click | May listahan ng mga pasilidad na nakaayos ayon sa distansya, na sabay na nakikipag-interact sa mapa |
| Single-select na pop-up ang mga filter | Ginawang multi-select na chips ang mga filter (item, grupo, lugar, may stock lang, may konsultasyon ngayon, atbp.) |
| Ang stock ay "mayroon／wala" lang ang ipinapakita | Ganoon din: "may／walang stock" lang ang ipinapakita (hindi ini-publish ang raw na dami para maiwasang magkamali ang publiko sa kahulugan ng numero) |
| Walang navigation | Ang detail page ay may pagtawag sa telepono (`tel:`) at link ng ruta sa Google Maps |
| Hindi maibabahagi ang estado ng filter | Ang mga kondisyon ng filter at napiling pasilidad ay ine-encode sa URL (URL hash); maaaring direktang ibahagi, i-bookmark, at maibalik gamit ang back/forward |
