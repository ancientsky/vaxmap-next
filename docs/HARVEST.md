# 2026-09-21 資料快照擷取方式

`data/raw/vaxmap_raw_20260921-1128.json.gz` 是本原型使用的唯一一次資料擷取紀錄，經
`scripts/normalize.mjs` 轉換為 `public/data/hospitals.json`。以下記錄擷取方式，
供日後需要重新擷取，或評估是否要換成正式資料串接時參考。

## 擷取方式

由於現站 `POST /Home/GetHospitalData` 沒有開放 CORS、且需要 `X-Requested-With` 標頭，
擷取程式是在瀏覽器分頁**於現站自身網域內**（vaxmap.cdc.gov.tw）執行，直接呼叫該站原本就會
呼叫的內部 API，等同模擬使用者反覆操作地圖。

1. **切分範圍**：以四分樹（quadtree）方式切分全臺經緯度範圍
   `緯度 21.5–26.5 / 經度 117.5–122.5`（涵蓋本島＋金門、馬祖、澎湖），從最外層一個大矩形開始。
2. **逐格分頁擷取**：對每個矩形格子，重複以「已取得的院所 id 清單」作為 `ids[]` 參數重新送出
   POST 請求，每次回應會排除已回傳過的院所；當某次回應筆數 **少於 20 筆**時，代表這個格子已經
   擷取完畢。
3. **格子過大時再切分**：當單一格子累積到 **500–700 個 id** 時就主動切成 4 個子格重新擷取，
   而不是繼續往下分頁——這是因為 ASP.NET 的表單欄位數量上限，`ids[]` 塞進過多值會導致請求本身
   被伺服器拒絕或截斷，切分成更小範圍可以讓每個格子的 id 數量維持在安全範圍內。
4. **節流**：每次請求之間間隔約 **300 毫秒**，避免對現站造成過大負載。
5. **總量**：全程約 **277 次請求**，累積下載 **約 97 MB**（因為每次回應都附帶伺服器端算繪好的
   HTML 內容），最終取得 **4,661 筆**院所資料（`normalize.mjs` 再依醫事機構代碼去除來源本身的 8 筆重複，輸出 4,653 筆）。

## 擷取後的精簡處理

原始回應中每筆院所資料包含大量本原型用不到的欄位，擷取程式在寫檔前先做以下裁剪，
把原始的 API 回應精簡成 `data/raw/*.json.gz` 目前的樣子：

- 移除 `InfoWindowMessage` 等伺服器端算繪好的 HTML 字串（現站地圖資訊視窗用，本原型自己畫 UI）；
- 移除 `DefaultVacc` 這類「品項目錄」重複資訊（每筆院所都會夾帶一份完整目錄，實際上全站共用
  同一份，改成前端自己維護 `scripts/normalize.mjs` 內的 `VACCINES` 常數）；
- 移除值為空字串／`false`／`null` 的欄位；
- 最終以 gzip 壓縮，從原始 JSON 壓到約 **400 KB**。

## 這只是權宜作法

這個「開分頁手動打 API、再裁剪存檔」的流程**僅適合一次性原型驗證**，不建議作為正式資料更新機制：

- 沒有排程、需要人工執行；
- 直接呼叫現站內部 API，屬於非正式、未公開文件化的介面，介面異動時擷取程式會直接失效；
- 297 次請求／97 MB 傳輸量若排程頻繁執行，會對現站造成不必要的負擔。

正式作法請見 `README.md` 的「建議的正式資料串接方式」一節：由伺服器端排程直接從資料庫匯出
`hospitals.json`，或由現站團隊開一支回傳全量資料的 JSON 端點。

## 自動化版本（scripts/harvest.mjs）

第一次快照是在瀏覽器分頁內執行的；之後改用 `scripts/harvest.mjs`，邏輯相同，但由 Node 直接對現站發請求
（伺服器對伺服器，不受瀏覽器跨網域限制）。差異只有三點：先取一次首頁以帶上伺服器給的 cookie；
格子在已知院所達 500 家時就先四分，單次請求的 `ids[]` 最多約 700 個；並加上保險絲
（最多 1,500 次請求、40 分鐘、少於 4,000 家視為失敗）。以模擬伺服器測試時約 250 次請求可取回全部院所。

已確認的限制：現站不接受境外連線。2026-09-21 從 GitHub Actions 的執行機器（國外）實測，連線逾時
（`UND_ERR_CONNECT_TIMEOUT`）。擷取必須在國內的機器上執行，作法見 README「部署到 GitHub Pages」
（`scripts/publish-data.sh` 與 `scripts/install-updater.sh`）。
