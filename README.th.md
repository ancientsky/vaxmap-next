# แผนที่วัคซีนและยาต้านไวรัสไข้หวัดใหญ่ (vaxmap-next)

**語言／Language：** [繁體中文](README.md) ・ [English](README.en.md) ・ [日本語](README.ja.md) ・ [한국어](README.ko.md) ・ [Bahasa Indonesia](README.id.md) ・ [Tiếng Việt](README.vi.md) ・ ไทย ・ [Filipino](README.tl.md)

นี่คือ**ต้นแบบแนวคิด (Proof of Concept)** ของ "แผนที่วัคซีนและยาต้านไวรัสไข้หวัดใหญ่" (vaxmap.cdc.gov.tw) ของศูนย์ควบคุมและป้องกันโรคแห่งไต้หวัน (Taiwan CDC) กระทรวงสาธารณสุขและสวัสดิการ
สร้างขึ้นเพื่อสาธิตประสบการณ์ใช้งานฝั่งหน้าเว็บที่เร็วและใช้งานง่ายกว่าเว็บไซต์ปัจจุบัน **นี่ไม่ใช่เว็บไซต์ทางการ** ไม่ได้ติดตั้งบนโดเมนของหน่วยงานรัฐใด ๆ และข้อมูล
**ไม่ใช่ข้อมูลแบบเรียลไทม์** แต่เป็นสแนปช็อตที่ดึงจากเว็บไซต์ปัจจุบันวันละสองครั้ง (สแนปช็อตแรกคือ 2026-09-21 ดูกลไกการอัปเดตได้ที่ "วิธีอัปเดตข้อมูล" และ "การติดตั้งบน GitHub Pages") หากรับช่วงต่อโปรเจกต์นี้
ขอแนะนำให้อ่าน `docs/DATA_SCHEMA.md` (สัญญาข้อมูลฝั่งหน้าเว็บ) และ `docs/HARVEST.md` (สแนปช็อตมาจากไหนและมีข้อจำกัดอะไรบ้าง) ก่อน

## นี่คืออะไร และไม่ใช่อะไร

- คือ: ต้นแบบเว็บไซต์แบบสแตติกล้วน ทำงานได้โดยอ่านไฟล์ JSON ไฟล์เดียว เพื่อสาธิตการออกแบบตัวกรอง รายการ การโต้ตอบกับแผนที่ และ URL ที่แชร์ได้
- ไม่ใช่: ระบบที่ใช้งานจริง แหล่งข้อมูลแบบเรียลไทม์ หรือสิ่งที่มาแทนเว็บไซต์ปัจจุบัน ระยะทาง สต็อก และช่วงเวลาให้บริการล้วนเป็นข้อมูล ณ เวลาที่ทำสแนปช็อต
  **ก่อนไปรับวัคซีนจริงต้องโทรสอบถามสถานพยาบาลก่อนเสมอ**

## โครงสร้างโฟลเดอร์

```

  index.html
  css/app.css
  js/
    app.js              Main flow / state management / view assembly
    ui.js               DOM builders (pure functions, no business logic)
    map.js              Leaflet map wrapper
    logic.js            Pure functions (time, filtering, sorting, URL state) - no DOM dependency, unit-testable
    i18n.js             Multilingual support: locale detection, string lookup, locale switching (see docs/I18N.md)
    data-source.js       Data source adapter (currently reads local JSON; switching to a live API only changes this file)
  data/hospitals.json   Normalized facility data (the only data file the front end reads)
  i18n/<lang>.json      UI strings (zh-Hant source text, en, ja, ko, id, vi, th, tl)
  vendor/leaflet, vendor/markercluster   Third-party map libraries (bundled static files, deployed together with public/)

scripts/
  dev-server.mjs        Zero-dependency static server for local development
  harvest.mjs           Harvests nationwide facility data from the current site → data/raw/*.json.gz (interim approach, see docs/HARVEST.md)
  normalize.mjs         Conversion script: data/raw/*.json.gz → public/data/hospitals.json
  romanize.mjs          English (Latin-alphabet) transliteration of facility names / addresses / districts, called by normalize.mjs
  keep-live-data.mjs    At deploy time, uses the newer data from the data branch (or the live site), sanitizing it first (used by GitHub Actions)
  publish-data.sh       Runs on a machine in Taiwan: harvest → check → push to the data branch → trigger deployment
  install-updater.sh    Installs a daily schedule on a Linux machine in Taiwan (systemd user timer)
.github/workflows/
  deploy.yml            Deploys to GitHub Pages (site from main, data from the data branch)
  freshness.yml         Checks daily whether the data has gone more than 36 hours without an update, and sends an email if it is too old
docs/
  DATA_SCHEMA.md        Format contract for public/data/hospitals.json
  HARVEST.md            How the 2026-09-21 snapshot was harvested, and known limitations
  I18N.md               Localization rules, medical terminology glossary, full key list (for translators)
  BASEMAP.md            Evaluation of basemap place-name languages, measured evidence and decisions
tests/
  logic.test.mjs        Unit tests for logic.js (node:test)
  i18n.test.mjs         Locale file consistency (keys, parameters, placeholder files)
  data.test.mjs         Data quality tests for hospitals.json, cross-validated against data/raw
  e2e.spec.mjs          Playwright end-to-end smoke tests (desktop + mobile)
  a11y.spec.mjs         Accessibility checks (report only, no fixes)
  harvest.test.mjs      Verifies harvest.mjs against a mock source server (mock-source.mjs)
  romanize.test.mjs     Hand-checked examples of English transliteration (names, addresses, edge cases)
```

## รันในเครื่อง

เซิร์ฟเวอร์สำหรับพัฒนาผูกกับเครื่องตัวเองเท่านั้น (127.0.0.1) โดยค่าเริ่มต้น หากต้องการให้โทรศัพท์ในเครือข่ายเดียวกันเข้ามาทดสอบ ให้เริ่มด้วย `HOST=0.0.0.0 npm run dev`

ข้อกำหนด: Node.js 18 ขึ้นไป (`"type": "module"` ใช้ ES modules และ `node:test`) โปรเจกต์นี้**ไม่มีขั้นตอน build**
ทุกอย่างใต้ `public/` คือผลลัพธ์ที่นำไปติดตั้งได้ทันที `leaflet`／`leaflet.markercluster` อยู่ใน `devDependencies` เท่านั้น
สำหรับใช้สร้างไฟล์บันเดิลใต้ `public/vendor/` ใหม่ในอนาคต การรันจริงไม่ต้อง `npm install`
ข้อยกเว้นเดียวคือ**การสร้างข้อมูล**: `scripts/normalize.mjs` ใช้ `pinyin-pro` (devDependency ใช้พจนานุกรมในเครื่อง ไม่ต่ออินเทอร์เน็ต) เพื่อสร้างการถอดเสียงเป็นอักษรอังกฤษ
ต้อง `npm install` ก่อนรัน `npm run normalize`／`update-data` (`publish-data.sh` จะรัน `npm ci` ให้อัตโนมัติเมื่อไม่มีแพ็กเกจ)

```bash
npm run dev        # Start http://localhost:5173/ (override with the PORT environment variable)
```

## รันการทดสอบ

```bash
npm test           # Unit tests + data quality tests (node --test)
npm run test:e2e   # Playwright end-to-end smoke tests (desktop 1440x900, mobile 390x844)
npm run test:a11y  # Accessibility checks (reports issues only, never modifies any file)
```

`test:e2e` และ `test:a11y` ต้องติดตั้ง `playwright` แบบ global ไว้ในสภาพแวดล้อมแล้ว (โปรเจกต์นี้สมมติเวอร์ชัน 1.56) และติดตั้งเบราว์เซอร์ไว้ล่วงหน้า
(`PLAYWRIGHT_BROWSERS_PATH` ชี้ไปยังไดเรกทอรีที่ติดตั้ง Chromium ไว้แล้ว) สคริปต์ทั้งสองจะเริ่ม
`scripts/dev-server.mjs` เองบนพอร์ตที่ว่างแบบสุ่ม และปิดให้อัตโนมัติเมื่อทดสอบเสร็จ **ไม่ต้องเริ่มเซิร์ฟเวอร์เองอีก**

## การติดตั้งใช้งาน (Deployment)

`public/` เป็นไดเรกทอรีเดียวที่ต้องขึ้นระบบจริง คัดลอกไปยังโฮสต์สแตติกใดก็ได้ (Nginx, IIS, S3+CDN, GitHub Pages ฯลฯ)
ไม่ต้องใช้โปรแกรมฝั่งเซิร์ฟเวอร์หรือฐานข้อมูลใด ๆ

### ข้อควรระวังในการติดตั้งบน IIS

- **MIME type**: ตรวจสอบว่า `.json` แมปกับ `application/json` (โดยทั่วไป IIS มีให้ในตัวอยู่แล้ว หากไม่มีให้เพิ่มใน
  `web.config` ว่า `<staticContent><mimeMap fileExtension=".json" mimeType="application/json" /></staticContent>`)
- **การบีบอัดไฟล์สแตติก**: เปิด Static Compression ของ IIS (`httpCompression`／`urlCompression`)
  `hospitals.json` ก่อนบีบอัดมีขนาดประมาณ 1.9 MB เมื่อเปิด gzip จะเหลือประมาณ 330 KB ซึ่งส่งผลต่อประสบการณ์ของผู้ใช้เครือข่ายมือถือมาก
- **HTTP header ที่แนะนำ**:
  | Header | ค่าที่แนะนำ | เหตุผล |
  |---|---|---|
  | `Content-Security-Policy` | ซิงก์การตั้งค่า `<meta http-equiv>` ที่มีอยู่ใน `public/index.html` ไปไว้ที่ระดับเซิร์ฟเวอร์ (`frame-ancestors 'none'` ต้องตั้งที่ระดับ HTTP header เพราะแท็ก `<meta>` ประกาศ `frame-ancestors` ไม่ได้) | ป้องกันการถูกฝังใน iframe (clickjacking) และจำกัดแหล่งที่มาของสคริปต์／สไตล์ |
  | `X-Content-Type-Options` | `nosniff` | ป้องกันความเสี่ยงจากการที่เบราว์เซอร์เดา MIME type เอง |
  | `Referrer-Policy` | `strict-origin-when-cross-origin` | ตั้งไว้แล้วใน `<meta name="referrer">` ที่ระดับเซิร์ฟเวอร์เพิ่มได้อีกชั้น |
  | `X-Frame-Options` | `DENY` (หากไม่ใช้ CSP `frame-ancestors`) | เหตุผลเดียวกัน เป็นมาตรการสำรองสำหรับเบราว์เซอร์รุ่นเก่า |
- **นโยบายแคช**:
  | พาธ | แคชที่แนะนำ | เหตุผล |
  |---|---|---|
  | `data/hospitals.json` | แคชสั้น (เช่น `Cache-Control: no-cache` หรือ `max-age=60~300`) | ข้อมูลอัปเดตเป็นระยะ แคชนานเกินไปจะทำให้ผู้ใช้เห็นสต็อกที่ล้าสมัย |
  | `vendor/**`、`css/**`、`js/**` | แคชยาว＋ใส่เวอร์ชัน (เช่น `max-age=31536000, immutable` ร่วมกับการใส่เลขเวอร์ชันในชื่อไฟล์หรือ query string) | ต้องทำให้แคชหมดอายุเฉพาะเมื่อเนื้อหาเปลี่ยน ช่วยลดการดาวน์โหลดซ้ำได้มาก |
  | `index.html` | แคชสั้นหรือไม่แคช | ให้แน่ใจว่าผู้ใช้ได้รับ reference ของทรัพยากรล่าสุด |

  ปัจจุบัน `scripts/dev-server.mjs` (ใช้สำหรับพัฒนาในเครื่องเท่านั้น) ตอบกลับ `Cache-Control: no-cache` กับทุกไฟล์ ส่วนในสภาพแวดล้อมจริง
  ให้ตั้งค่าที่ชั้น IIS／CDN ตามตารางข้างต้น ไม่ต้องแก้ไขเนื้อหาใน `public/` เอง

## วิธีอัปเดตข้อมูล (แนวทางปัจจุบัน)

`npm run update-data` จะทำสามอย่างตามลำดับ: `scripts/harvest.mjs` ดึงข้อมูลสถานพยาบาลทั่วประเทศจากเว็บไซต์ปัจจุบัน แล้วบันทึกเป็น
`data/raw/vaxmap_raw_YYYYMMDD-HHmm.json.gz`; `scripts/normalize.mjs` แปลงไฟล์ดิบล่าสุดเป็น
`public/data/hospitals.json` (สัญญาของรูปแบบไฟล์ดูที่ `docs/DATA_SCHEMA.md`); สุดท้ายรันการตรวจสอบข้อมูล หากขั้นตอนใดล้มเหลวจะหยุดทันที
ไม่ทิ้งข้อมูลที่ทำไม่ครบขึ้นระบบ รายละเอียดและข้อจำกัดของการดึงข้อมูลดูที่ `docs/HARVEST.md`

การดึงข้อมูลครบหนึ่งรอบส่งคำขอไปยังเว็บไซต์ปัจจุบันประมาณ 280 ครั้ง ถ่ายโอนข้อมูลเกือบ 100 MB ใช้เวลา 10–15 นาที ข้อมูลต้นทางเป็นรายงานรายวันจากสถานพยาบาล
**อัปเดตวันละ 1–2 ครั้งก็เพียงพอแล้ว โปรดอย่าเพิ่มความถี่หรือลดช่วงเวลาหน่วงระหว่างคำขอ** เว็บไซต์ปัจจุบันไม่รับการเชื่อมต่อจากต่างประเทศ การดึงข้อมูลจึงต้องรันบนเครื่องในไต้หวัน วิธีอัปเดตอัตโนมัติร่วมกับ GitHub Pages ดูในหัวข้อถัดไป

นี่ยังเป็น**แนวทางชั่วคราว** แนวทางที่เป็นทางการคือให้ฝั่งเซิร์ฟเวอร์ส่งออกข้อมูลโดยตรง (ดู "แนวทางเชื่อมต่อข้อมูลที่แนะนำสำหรับใช้งานจริง")

## หลายภาษา

ส่วนติดต่อผู้ใช้รองรับภาษาจีนตัวเต็ม (ค่าเริ่มต้น), English, 日本語, 한국어, Bahasa Indonesia, Tiếng Việt, ไทย, Filipino
สลับได้จากเมนูไอคอนลูกโลกที่ส่วนหัว (ไม่โหลดหน้าใหม่) ภาษาจะถูกกำหนดตามลำดับจาก `#lang=en` ใน URL, ตัวเลือกครั้งก่อน (localStorage),
ภาษาของเบราว์เซอร์ และหากไม่มีจะใช้จีนตัวเต็ม ภาษาที่ไม่ใช่ค่าเริ่มต้นจะถูกเขียนลงใน URL ที่แชร์ได้ ชื่อเทศมณฑล／เมืองจะถูกแปล และค้นหาด้วยชื่อเป็นภาษาต่างประเทศได้ (เช่น “Taipei”)

**การถอดเสียงชื่อและที่อยู่สถานพยาบาลเป็นอักษรอังกฤษ**: ในแต่ละรายการของ `hospitals.json` มี `nameEn`、`addrEn`、`cityEn`、`distEn` เพิ่มเติม
(`scripts/romanize.mjs` สร้างด้วยกฎ: ศัพท์การแพทย์ค้นจากตารางคำศัพท์แล้วแปลเป็นอังกฤษ, คำนามเฉพาะใช้ฮั่นอวี่พินอิน, เทศมณฑล／เมืองและเขตปกครองใช้ชื่ออังกฤษทางการ,
ที่อยู่เรียงตามลำดับแบบอังกฤษของไปรษณีย์ เช่น 「林文正耳鼻喉科診所」→ “Linwenzheng ENT Clinic”、「臺北市北投區明德路92號1樓」→
“1F, No. 92, Mingde Rd., Beitou District, Taipei City”) ค่า `meta.script` ในไฟล์ภาษากำหนดวิธีแสดงผล: `latin` (en、ko、id、vi、th、tl)
ใช้อังกฤษเป็นหลัก และวางต้นฉบับภาษาจีนไว้บรรทัดที่สอง (สะดวกในการแสดงให้คนขับแท็กซี่หรือเคาน์เตอร์ดู); `han` (จีนตัวเต็ม, ญี่ปุ่น) ใช้ภาษาจีนเป็นหลัก และภาษาญี่ปุ่นจะมีชื่อภาษาอังกฤษแนบเพิ่ม
การค้นหาในทุกภาษาจะเทียบทั้งฟิลด์ภาษาจีนและภาษาอังกฤษพร้อมกัน (“Beitou”、“Mingde”、“ENT”、“Lin Wen Zheng” ล้วนค้นเจอ) การถอดเสียงสร้างจากกฎของเครื่อง
ไม่ใช่ชื่อแปลอย่างเป็นทางการ ชื่อหรือที่อยู่บางรายการอาจไม่ถูกต้องทั้งหมด

- **ตำแหน่งของสตริง**: `public/i18n/<lang>.json` เป็น key → สตริงแบบแบน `zh-Hant.json` คือต้นฉบับ
- **กฎของ key**: แบ่ง namespace ตามฟีเจอร์ (`filters.today`、`detail.call`、`status.ok.text`); พารามิเตอร์อย่าง `{n}` ต้องคงไว้;
  เมื่อจำนวนเป็น 1 พอดีให้ใช้ `<key>.one`; ห้ามมี HTML ไฟล์ภาษาทุกไฟล์ต้องมี key เหมือนกับภาษาจีนตัวเต็มทุกประการ (`npm test` จะตรวจสอบ)
- **เพิ่มภาษาใหม่**: เพิ่มรหัสใน `SUPPORTED_LANGS` ของ `logic.js` → คัดลอก `en.json` แก้ `meta.*` ตั้ง `"_status": "placeholder"`
  → เพิ่มตัวเลือกใน `#lang-select` ของ `index.html` → `npm test` ขั้นตอนโดยละเอียดและตารางเทียบศัพท์การแพทย์ดูที่ `docs/I18N.md`
- **สถานะการตรวจทาน** (`_status` ในไฟล์): `zh-Hant` เป็นต้นฉบับ, `en` เสร็จแล้ว; `ja`、`ko`、`id`、`vi`、`th`、`tl` เป็น
  `placeholder` (แสดงเป็นภาษาอังกฤษชั่วคราว รอการแปล)

## การติดตั้งบน GitHub Pages (รวมการอัปเดตข้อมูลอัตโนมัติทุกวัน)

**ข้อจำกัดสำคัญ: เว็บไซต์ปัจจุบันของ Taiwan CDC ไม่รับการเชื่อมต่อจากต่างประเทศ** จากการทดสอบจริงเมื่อ 2026-09-21 เครื่องที่รัน GitHub Actions (ตั้งอยู่ต่างประเทศ) เชื่อมต่อไปยัง
`vaxmap.cdc.gov.tw` แล้วหมดเวลา (`UND_ERR_CONNECT_TIMEOUT`) ดังนั้นการดึงข้อมูลจึงรันบน GitHub ไม่ได้
จึงเปลี่ยนเป็น "เครื่องในไต้หวันดึงข้อมูล GitHub ทำหน้าที่ติดตั้งอย่างเดียว":

```
Linux machine in Taiwan (daily at 05:30, 12:30)  GitHub
  scripts/publish-data.sh                          
    ├─ harvest.mjs harvest → normalize.mjs → data checks  
    ├─ force-push hospitals.json to the data branch  ──►  data branch (always a single commit, so the repo does not grow)
    └─ gh workflow run deploy.yml             ──►  deploy.yml: take the site from main + the newer data from the data branch
                                                    → run sanitizing and checks again → deploy to Pages
```

`.github/workflows/deploy.yml` ทำงานเมื่อมีการ push ไปยัง `main` หรือถูกสั่งด้วยมือ／ถูก `publish-data.sh` เรียก: ดึง `hospitals.json`
จากสาขา `data` ผ่าน `scripts/keep-live-data.mjs --file` เพื่อทำความสะอาด และยืนยันว่าใหม่กว่าสแนปช็อตใน `main` จึงจะนำมาใช้ หากไม่มีสาขา `data`
จะใช้สแนปช็อตใน `main` ต่อไป `.github/workflows/freshness.yml` ตรวจสอบข้อมูลในสาขา `data` ทุกวันเวลา 09:00 Taipei time (UTC+8)
หากเกิน 36 ชั่วโมงไม่ได้อัปเดตจะทำให้การรันครั้งนั้นล้มเหลว และ GitHub จะส่งอีเมลแจ้งเจ้าของ repo (หมายความว่าเครื่องที่ดึงข้อมูลไม่ได้ทำงานหรือล้มเหลวต่อเนื่อง)
หน้าเว็บก็จะแสดง "สแนปช็อตข้อมูล" ว่า "ไม่ได้อัปเดตมา N วัน" ด้วย

การตั้งค่าครั้งแรก:

1. สร้าง repo สาธารณะบน GitHub แล้ว push โปรเจกต์นี้ขึ้นไป (สาขาเริ่มต้นต้องเป็น `main`)
2. ไปที่ Settings → Pages ของ repo ตั้ง Source เป็น **GitHub Actions** แล้วรันเวิร์กโฟลว์ "deploy" อีกครั้ง
3. บนเครื่อง Linux ที่**อยู่ในไต้หวันและเชื่อมต่อเว็บไซต์ปัจจุบันได้** (ต้องมี git, Node.js 20 ขึ้นไป, GitHub CLI ที่รัน `gh auth login` แล้ว)
   เข้าไปที่โฟลเดอร์โปรเจกต์แล้วลองรันด้วยมือก่อนหนึ่งครั้ง: `npm run publish-data` หากสำเร็จ เวลาสแนปช็อตบนเว็บไซต์จะอัปเดตภายใน 10–15 นาที
4. รัน `scripts/install-updater.sh` เพื่อติดตั้งตารางเวลารายวัน สคริปต์จะสร้างโฟลเดอร์เฉพาะแยกต่างหาก
   (`~/.local/share/vaxmap-updater` แยกจากโฟลเดอร์ที่คุณแก้โค้ด และซิงก์ `main` อัตโนมัติก่อนรันทุกครั้ง)
   และตั้งค่า systemd user timer รอบที่พลาดเพราะปิดเครื่องจะรันชดเชยหลังเปิดเครื่อง หากต้องการถอนการติดตั้งใช้ `scripts/install-updater.sh --uninstall`

ไม่แนะนำให้เปลี่ยนไปใช้เครื่องรันแบบโฮสต์เองของ GitHub (self-hosted runner): บน repo **สาธารณะ** pull request ที่ใครก็ส่งเข้ามา
อาจทำให้โค้ดรันบนเครื่องนั้นได้ และ GitHub เองก็ไม่แนะนำให้ใช้แบบนี้ แนวทางข้างต้นต้องการเพียงให้เครื่องนั้น "push ออกไปข้างนอก" โดยไม่รับคำสั่งจากภายนอกใด ๆ

ข้อควรทราบเมื่อใช้ GitHub Pages: แผนฟรีของ Pages ต้องใช้ repo สาธารณะ; Pages กำหนด HTTP header เองไม่ได้
ดังนั้นในบรรดา header ที่แนะนำในหัวข้อ IIS ข้างต้น จะมีผลเฉพาะส่วนที่ `<meta>` ใน `index.html` แสดงได้ (`frame-ancestors` ไม่มีผล);
Pages แคชทุกไฟล์คงที่ประมาณ 10 นาที หลังอัปเดตข้อมูลผู้ใช้จะเห็นได้ช้าสุด 10 นาที

## แนวทางเชื่อมต่อข้อมูลที่แนะนำสำหรับใช้งานจริง

API `POST /Home/GetHospitalData` ของเว็บไซต์ปัจจุบันมีข้อจำกัดต่อไปนี้ ทำให้ไม่เหมาะให้หน้าเว็บเรียกโดยตรง:

- แต่ละครั้งที่เรียกจะคืนข้อมูลสถานพยาบาลเพียง **20 รายการ** การจะได้ทั้งหมดราว 4,660 รายการต้องเรียกแบ่งหน้าประมาณ **280 ครั้ง**;
- แต่ละการตอบกลับมีขนาดประมาณ 390 KB และ**มี HTML ที่เรนเดอร์ฝั่งเซิร์ฟเวอร์ปนอยู่** (ไม่ใช่รูปแบบข้อมูลที่สะอาด) คำนวณแล้วการดึงข้อมูลทั้งหมด
  ต้องถ่ายโอนเกือบ **97 MB**;
- ต้องส่ง header `X-Requested-With: XMLHttpRequest` จึงจะถูกรับ;
- **ไม่เปิด CORS** เบราว์เซอร์เรียกข้ามโดเมนโดยตรงไม่ได้

**แนวทางที่แนะนำ**: สร้าง**งานตามกำหนดเวลา (scheduled job)** ที่ฝั่งแบ็กเอนด์ (เซิร์ฟเวอร์ที่เว็บไซต์ปัจจุบันอยู่ หรือสภาพแวดล้อมที่มีสิทธิ์เข้าถึงฐานข้อมูลต้นทาง)
ทุก N นาที (เช่น 5–15 นาที ตามความถี่การอัปเดตข้อมูล) ให้ส่งออกจากฐานข้อมูลโดยตรงและเอาต์พุตเป็น
`hospitals.json` ในรูปแบบตาม `docs/DATA_SCHEMA.md` (หลัง normalize ประมาณ 1.9 MB บีบอัด gzip แล้วประมาณ 330 KB; การถอดเสียงเป็นอังกฤษใช้ `scripts/romanize.mjs` ต่อได้)
แล้วเผยแพร่ไปยังโฮสต์ไฟล์สแตติกหรือ CDN

อีกทางเลือกที่ทำได้คือให้ทีมของเว็บไซต์ปัจจุบันเพิ่ม**JSON endpoint ที่คืนข้อมูลทั้งหมด** (แบ่งหน้าหรือไม่แบ่งก็ได้ แต่ต้องเปิด
CORS หรือติดตั้งบนโดเมนเดียวกัน) ผลลัพธ์เทียบเท่ากับการส่งออกตามกำหนดเวลาข้างต้น

ไม่ว่าจะเลือกแบบใด ฝั่งหน้าเว็บเพียงเปลี่ยนไฟล์ `public/js/data-source.js` ไฟล์เดียว (เปลี่ยน `fetch('./data/hospitals.json')`
เป็นการเรียก endpoint ใหม่ และตรวจสอบให้แน่ใจว่าออบเจกต์ที่คืนมายังเป็นโครงสร้าง `{ meta, vaccines, groups, hospitals }`)
โค้ดส่วนอื่นไม่ต้องแก้เลย

## ความมั่นคงปลอดภัย

**ไลบรารีภายนอก** (ตรวจสอบเมื่อ 2026-09-21): Leaflet 1.9.4 และ leaflet.markercluster 1.5.3 เป็นเวอร์ชันเสถียรล่าสุดบน npm
(Leaflet 2.0 ยังอยู่ในสถานะ alpha และเปลี่ยนเป็น ESM ล้วน ตัด `L` แบบ global ออก markercluster ยังไม่รองรับ จึงยังไม่แนะนำให้อัปเกรด)
ไฟล์ใน `public/vendor/` ตรงกับแพ็กเกจ npm ทุกบิต `npm run verify-vendor` ตรวจสอบด้วย sha256 และ `npm test` ก็รวมการตรวจนี้ด้วย
`npm audit` ได้ 0 รายการ Leaflet มีรายงาน CVE-2025-69993 ที่ยังไม่มีเวอร์ชันแก้ไข (`bindPopup()` จะเรนเดอร์สตริงที่ส่งเข้าไปเป็น HTML
ผู้ดูแลถือว่าเป็นพฤติกรรมเดิมที่ระบุไว้ในเอกสารอยู่แล้ว) เว็บไซต์นี้**ไม่ได้ใช้** popup／tooltip สตริงข้อมูลทั้งหมดเขียนผ่าน `textContent` หรือ attribute จึงไม่ได้รับผลกระทบ

**การป้องกันฝั่งหน้าเว็บ**: CSP ของ `index.html` ไม่อนุญาตสคริปต์และสไตล์แบบ inline และเปิดให้เฉพาะรูปภาพจากโดเมนแผนที่พื้นฐานสองโดเมน นอกจากนี้เปิดใช้ Trusted Types
(`public/js/trusted-types.js`) อนุญาตเฉพาะสตริง HTML คงที่ของ Leaflet และ `map.js` — หากภายหลังแก้ HTML ของหมุดหรือ
ข้อความลิขสิทธิ์ของแผนที่พื้นฐาน ต้องอัปเดต allowlist ในไฟล์นั้นพร้อมกัน ไม่เช่นนั้นการทดสอบ e2e จะล้มเหลวเพราะข้อผิดพลาดในคอนโซล ลิงก์ภายนอกใช้ `rel="noopener noreferrer"` เสมอ
URL สำหรับจองรับเฉพาะ https ตำแหน่งของผู้ใช้อยู่ในหน่วยความจำเท่านั้น ไม่ถูกเขียนลง URL, พื้นที่จัดเก็บ หรือคำขอใด ๆ (แต่เมื่อซูมแผนที่เข้าไป เซิร์ฟเวอร์แผนที่พื้นฐานอาจอนุมานพื้นที่คร่าว ๆ ได้จากคำขอไทล์)

**ไปป์ไลน์ข้อมูล**: ถือว่าการตอบกลับจากเว็บไซต์ต้นทางไม่น่าเชื่อถือเสมอ `scripts/sanitize.mjs` สร้างแต่ละฟิลด์ที่จะเผยแพร่ขึ้นใหม่ด้วย allowlist
(ตัดอักขระควบคุมและอักขระควบคุมทิศทางข้อความสองทิศทาง, จำกัดความยาว, ตรวจช่วงค่าตัวเลขและช่วงพิกัด, ตรวจรูปแบบโทรศัพท์และ URL)
`normalize.mjs` และ `keep-live-data.mjs` ใช้มันเป็นด่านสุดท้ายทั้งคู่ `harvest.mjs` กำหนดเพดานสำหรับการตอบกลับครั้งเดียว ปริมาณการถ่ายโอนรวม จำนวนรายการต่อหน้า และจำนวนรายการทั้งหมด
การทดสอบที่เกี่ยวข้องอยู่ใน `tests/security.test.mjs`

**GitHub Actions**: แต่ละงานใช้สิทธิ์ต่ำสุด (เฉพาะ deploy ที่มี `pages: write` ไม่มีงานใดเขียนลง repo ได้)
ทุก action ถูกตรึงไว้กับ commit SHA เต็ม `${{ }}` ส่งผ่าน `env:` เสมอโดยไม่เขียนลงในคำสั่งโดยตรง และ checkout ไม่เก็บ credential
เมื่ออัปเกรดเวอร์ชันของ action ให้ตรวจสอบใหม่และอัปเดต SHA แนะนำให้ไปที่ Settings → Environments → github-pages ของ repo และยืนยันว่าอนุญาตให้ติดตั้งจากสาขา `main` เท่านั้น

**ข้อจำกัดของ GitHub Pages**: ตั้ง HTTP header ไม่ได้ จึงไม่มี `frame-ancestors`／`X-Frame-Options` (ป้องกันการถูกเว็บไซต์อื่นฝัง)
เว็บไซต์นี้ไม่มีสถานะการล็อกอินหรือการดำเนินการที่ละเอียดอ่อนซึ่งอาจถูกหลอกให้คลิก ความเสี่ยงจึงต่ำ หากเปลี่ยนไปติดตั้งบนโฮสต์ที่ตั้ง header ได้ โปรดเพิ่มเข้าไป

## แผนที่พื้นฐาน

แผนที่พื้นฐานเลือกตามภาษาของส่วนติดต่อผู้ใช้ เพื่อให้อ่านชื่อสถานที่ออก (กระบวนการประเมินและหลักฐานจากการทดสอบจริงดูที่ `docs/BASEMAP.md`):

- **จีนตัวเต็ม**: "แผนที่อิเล็กทรอนิกส์แบบทั่วไป (通用版電子地圖)" `EMAP` ของสำนักงานสำรวจและทำแผนที่แห่งชาติ (NLSC) (ชื่อสถานที่เป็นภาษาจีน โหลดเร็วกว่าสำหรับผู้ใช้ในไต้หวัน) หากล้มเหลวจะใช้ไทล์ทางการของ OpenStreetMap
- **ญี่ปุ่น**: เหมือนจีนตัวเต็ม (ผู้ใช้ภาษาญี่ปุ่นอ่านชื่อถนนที่เป็นอักษรฮั่นได้ และตรงกับป้ายถนน)
- **ภาษาอื่น** (en、ko、id、vi、th、tl): "แผนที่อิเล็กทรอนิกส์ทั่วไปไต้หวัน EN" `EMAP8` ของ NLSC (ชื่อสถานที่ภาษาอังกฤษทั่วไต้หวัน) หากล้มเหลวจะใช้ OpenStreetMap และแสดงข้อความแจ้งว่า "ชื่อสถานที่อาจแสดงเป็นภาษาจีน" ปัจจุบันไม่มีแหล่งที่ไม่ต้องใช้คีย์ซึ่งให้ชื่อถนนภาษาเกาหลี ดังนั้น ko ก็ใช้ภาษาอังกฤษเช่นกัน

**ผู้ใช้สลับเองได้**: ในคำอธิบายสัญลักษณ์ (เดสก์ท็อปอยู่มุมซ้ายล่าง ขยายไว้เป็นค่าเริ่มต้น; มือถืออยู่มุมขวาบน พับไว้เป็นค่าเริ่มต้น) มีปุ่มตัวเลือกวิทยุ "แผนที่พื้นฐาน" — ส่วนติดต่อผู้ใช้ภาษาจีน／ญี่ปุ่นเลือกได้
"แผนที่อิเล็กทรอนิกส์แบบทั่วไป (通用版電子地圖)" หรือ "OpenStreetMap" ส่วนภาษาต่างประเทศเลือกได้ “NLSC (English)”, NLSC ฉบับภาษาจีน (ชื่อสถานที่ตรงกับป้ายถนน) และ “OpenStreetMap”
เลือกแล้วเปลี่ยนแผนที่ทันที แถบลิขสิทธิ์เปลี่ยนตาม ตัวเลือกถูกจำไว้ใน localStorage ของเบราว์เซอร์ที่คีย์ `vaxmap.basemap` โดย**จำแยกกันระหว่างชื่อสถานที่ภาษาจีนกับชื่อสถานที่ภาษาต่างประเทศ**
และเมื่อสลับภาษาจะนำค่าของแต่ละกลุ่มไปใช้ หากแผนที่ที่เลือกโหลดไม่สำเร็จ ระบบยังคงเปลี่ยนไปใช้ตัวถัดไปอัตโนมัติและแสดงข้อความแจ้ง และปุ่มตัวเลือกวิทยุจะเปลี่ยนไปเลือกแผนที่ที่แสดงอยู่จริง

เมื่อสลับภาษา แผนที่พื้นฐานจะเปลี่ยนทันทีโดยไม่โหลดหน้าใหม่ ลำดับกำหนดโดย `BASEMAP_CHAINS` ใน `public/js/map.js` (เลเยอร์แรกของแต่ละเชนคือค่าเริ่มต้น
ที่เหลือเป็นตัวสำรองตามลำดับ เลเยอร์ที่อยู่บนโฮสต์เดียวกันถือว่าใช้งานไม่ได้พร้อมกัน); `img-src` ของ CSP ใน `index.html` เปิดให้เฉพาะสองโดเมนนี้ (EMAP8 กับ EMAP อยู่โฮสต์เดียวกัน) ในการทดสอบ สามารถเพิ่มใน URL
`?tiles=nlsc`／`?tiles=osm`／`?tiles=nlscEn` เพื่อกำหนดแผนที่พื้นฐานเริ่มต้น (ต้องอยู่ในเชนของภาษาปัจจุบัน) เพิ่ม `?tiles=fail` เพื่อจำลองว่าแผนที่พื้นฐานเริ่มต้นใช้งานไม่ได้
หรือเพิ่มรูปแบบอย่าง `?tiles=fail:osm` เพื่อให้เฉพาะแผนที่พื้นฐานที่ระบุใช้งานไม่ได้
**ก่อนขึ้นระบบจริง** โปรดทำสิ่งต่อไปนี้ให้ครบ:

- ตรวจสอบ [นโยบายการใช้ไทล์ของ OSM](https://operations.osmfoundation.org/policies/tiles/) เซิร์ฟเวอร์ไทล์ทางการของ OSM
  ดำเนินงานด้วยเงินบริจาคและไม่รับประกันความพร้อมใช้งาน นโยบายระบุชัดว่าการใช้งานปริมาณมากต้องไม่พึ่งพามัน หากฝ่าฝืนอาจถูกบล็อกโดยไม่แจ้งล่วงหน้า
  ต้นแบบและการสาธิตที่มีทราฟฟิกต่ำไม่มีปัญหา หากจะใช้เป็นแผนที่พื้นฐานเริ่มต้นของบริการสาธารณะจริง แนะนำให้เปลี่ยนเป็นไทล์ที่โฮสต์เองหรือผู้ให้บริการไทล์เชิงพาณิชย์
  (MapTiler, Stadia, Mapbox ฯลฯ ซึ่งส่วนใหญ่ยังทำแผนที่จากข้อมูล OSM) ปัจจุบันค่าเริ่มต้นของทุกภาษาคือ NLSC โดย OSM ใช้เฉพาะเป็นตัวสำรองหรือเมื่อผู้ใช้เลือกเอง;
- คำอธิบายทางการของ WMTS ของ NLSC ระบุว่า "ผู้ใช้ไม่ต้องขออนุญาต" ก็เชื่อมต่อได้ แต่ไม่มีเพดานปริมาณทราฟฟิกหรือระดับการให้บริการ (SLA) ที่เปิดเผย แผนที่พื้นฐานเริ่มต้นของทุกภาษาอยู่ที่ NLSC (EMAP／EMAP8)
  ก่อนขึ้นระบบจริงและทราฟฟิกมากขึ้น แนะนำให้ยืนยันกับสำนักงานสำรวจและทำแผนที่แห่งชาติในนามของ Taiwan CDC (ดู `docs/BASEMAP.md`)

## เบราว์เซอร์ที่รองรับ

ใช้ API ของเบราว์เซอร์สมัยใหม่ (`fetch`, ES modules, CSS Grid, `<details>`, `prefers-color-scheme`)
เป้าหมายคือ Chrome, Edge, Firefox, Safari (รวม iOS Safari) ภายในสองปีที่ผ่านมา ไม่รองรับ IE11 และไม่ได้ทำ polyfill ที่เกี่ยวข้อง

## ข้อจำกัดที่ทราบ

- ข้อมูลเป็นสแนปช็อต (อัปเดตวันละสองครั้ง) ไม่ใช่เรียลไทม์ ก่อนรับวัคซีนโปรดโทรสอบถามสถานพยาบาลเพื่อยืนยันเสมอ
- ช่วงเวลาให้บริการแสดงช่วงเช้า／บ่าย／เย็นด้วย bitmask ที่แปลงจากข้อมูลของสำนักงานประกันสุขภาพแห่งชาติ (National Health Insurance Administration) เป็นเพียงช่วงเวลาโดยประมาณ ไม่ใช่ตารางตรวจที่แม่นยำ
- ชื่อและที่อยู่สถานพยาบาลคงข้อความต้นฉบับจากแหล่งข้อมูล (เช่น 「台北長庚紀念醫院」 เป็นชื่ออย่างเป็นทางการ) มีเพียงฟิลด์เทศมณฑล／เมืองและเขตปกครองที่ปรับให้ใช้ 「臺」 เหมือนกัน
- ชื่อสถานพยาบาลภาษาอังกฤษเป็นการถอดเสียงโดยเครื่อง (ชื่อคนเขียนเป็นพินอินติดกัน ใช้ชื่ออังกฤษทางการเพียงประมาณ 25 แห่งที่มีชื่อเสียง) ไม่ใช่ชื่อแปลอย่างเป็นทางการ
  ที่อยู่ภาษาอังกฤษสร้างตามรูปแบบของไปรษณีย์ และเก็บเฉพาะเลขที่บ้านแรก
- ข้อความส่วนติดต่อผู้ใช้ของหกภาษาต่างประเทศ (ja、ko、id、vi、th、tl) เป็นร่างแรกจาก AI ก่อนเผยแพร่สู่สาธารณะควรให้เจ้าของภาษาตรวจทาน
- สถานะอย่างตำแหน่งที่ตั้งและขอบเขตแผนที่จะไม่ถูกเขียนลงใน URL ที่แชร์ได้ (URL hash) จะแชร์เฉพาะเงื่อนไขตัวกรองและสถานพยาบาลที่เลือก
- ยังไม่ได้ทดสอบจริงบน IE／Android WebView รุ่นเก่า ไทล์แผนที่อาจโหลดล้มเหลวในสภาพแวดล้อมที่เครือข่ายไม่เสถียร (มีตัวสำรองอัตโนมัติและการสลับแผนที่พื้นฐานด้วยมือ)

## ความแตกต่างจากเว็บไซต์ปัจจุบัน

| ปัญหาของเว็บไซต์ปัจจุบัน | แนวทางของต้นแบบนี้ |
|---|---|
| ต้องปิดหน้าต่างประกาศที่บล็อกการใช้งานก่อนเข้าเว็บไซต์ | เปลี่ยนประกาศเป็นแบนเนอร์ (banner) ที่ส่วนหัวซึ่งปิดได้ ไม่บล็อกการใช้งาน |
| ข้อมูลถูกขอเป็นชุดละ 20 รายการด้วย XHR แบบซิงโครนัส | โหลด JSON ไฟล์เดียวรวดเดียว (ประมาณ 330 KB แบบ gzip รวมการถอดเสียงเป็นอังกฤษ) ฝั่งหน้าเว็บกรอง／เรียงลำดับในเครื่อง |
| หมุดบนแผนที่แสดงเพียง "เปิดตรวจ／หยุดตรวจ" | หมุดใช้รูปทรง＋สีแสดงสามสถานะพร้อมกัน คือ "เปิดตรวจวันนี้" และ "รายการที่เลือกมีสต็อกหรือไม่" |
| ไม่มีรายการ ต้องคลิกหมุดบนแผนที่เท่านั้น | มีรายการสถานพยาบาลเรียงตามระยะทาง โต้ตอบซิงก์กับแผนที่ |
| ตัวกรองเป็นหน้าต่างป็อปอัปแบบเลือกได้ทีละหนึ่ง | ตัวกรองเปลี่ยนเป็น chips ที่เลือกได้หลายตัว (รายการ กลุ่ม พื้นที่ เฉพาะที่มีสต็อก เปิดตรวจวันนี้ ฯลฯ) |
| สต็อกแสดงเพียง "มี／ไม่มี" | แสดงเพียง "มี／ไม่มีสต็อก" เช่นกัน (ไม่เผยแพร่จำนวนดิบ เพื่อป้องกันประชาชนเข้าใจความหมายของตัวเลขผิด) |
| ไม่มีฟังก์ชันนำทาง | หน้ารายละเอียดมีลิงก์โทรออก (`tel:`) และเส้นทาง Google Maps |
| แชร์สถานะตัวกรองไม่ได้ | เงื่อนไขตัวกรองและสถานพยาบาลที่เลือกถูกเข้ารหัสลง URL (URL hash) แชร์ได้โดยตรง บุ๊กมาร์กได้ และกู้คืนด้วยย้อนกลับ/ไปข้างหน้าได้ |
